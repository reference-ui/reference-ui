## Verdict up front

The accused generator is innocent. The crash is real (reproduced this
session: `ReferenceError: React is not defined` mounting `<Reference>` from
`dist/index.mjs`), but its cause is NOT the generated
`.reference-ui/types/types.mjs` and NOT any reference-rs emitter. Root cause:
`src/components/Reference/**/*.tsx` lib sources use JSX without importing
React, while the repo's tsup build emits the classic `React.createElement`
factory, which requires React in scope. Every other component in the repo
imports React; Reference's files are the sole violators. There is no
reference-rs-side fix that would not be masking — so this crew changed no
compiler code and hands the captain an exact lib-side fix list.

## Root cause (proven, not inferred)

1. `packages/reference-lib/tsup.config.ts` sets no `jsx` option, so tsup's
   esbuild emits the CLASSIC factory `React.createElement` for lib sources
   (whole dist is classic: every other file compiles to
   `ReactN.createElement` fed by its own `import * as ReactN from 'react'`).
2. The Reference lib sources were written automatic-runtime style (no React
   import). tsup emits bare `React.createElement` for them with no `React`
   binding anywhere in the bundle scope.
3. First throw is immediate on mount: `Reference` →
   `dist/index.mjs:72901` (`// src/components/Reference/Reference.tsx`,
   `React.createElement(ReferenceRuntimeProvider, ...)`) → `ReferenceError:
   React is not defined`. Stack trace captured this session (see probe).
4. Attribution sweep: ALL 78 bare-`React.*` uses in dist resolve to 18
   `src/components/Reference/**` files; ZERO come from the types.mjs/tasty
   generated chunks.

## H-4 report correction (packaging.md misattribution)

- Current `.reference-ui/types/types.mjs:1751` DOES contain
  `import * as React from "react"` directly above the
  `var AtSignIcon = React.forwardRef(` line. Mid-file ESM imports are hoisted
  and legal — the packaging crew read line 1753 without noticing 1751.
- The types.mjs chunk inside dist (`React2.forwardRef`, line 67058) is fed by
  `import * as React2 from "react"` (line 65079). Bound, correct, innocent.
- Note `ReferenceMemberList.tsx` DOES `import { useState } from 'react'` yet
  still crashes: a named hook import does not bind the `React` namespace the
  classic factory needs. The fix must add a namespace/default React import
  even there.

## Flags for HQ

1. H-4 is a lib-source bug, not a compiler bug. The brief's scope assumption
   ("typegen/tasty manifest emit path") does not match the defect; no
   reference-rs change exists that fixes it honestly.
2. tsup silently ignores `tsconfig.json`'s `"jsx": "react-jsx"` (emits
   classic regardless). That config mismatch is the trap the Reference
   authors fell into — consider either documenting the classic convention or
   an HQ decision to flip tsup to automatic.
3. `ReferenceMemberList` shows the subtle variant: a file CAN import from
   'react' and still crash under classic JSX if it lacks the namespace
   import. A lint rule (or a dist-time `React is not defined` smoke like the
   probe above) would catch the next instance at build time.
