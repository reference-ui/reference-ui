# H-3 options spike: arbitrary consumer numerics with ZERO consumer sync

Status: **COMPLETE** (read-only spike; no source modified, no commits)

Question (from packaging crew H-3 + HQ 140r thread): how could `maxW="140r"`
— a value existing nowhere in lib sources — paint with zero consumer sync?

## The mechanism in one paragraph

The runtime namer is already continuous: `name()` in
`packages/reference-rs/modules/atomic/js/namer/shape.ts` builds
`reference-ui__max-w_140r` from the prefix table + sanitized stem with no
sheet knowledge (`value.ts` `fromString` → legacy passthrough; rhythm is
never consulted at naming time). The shipped sheet is the only stepped
artifact: rules exist only for static literals the extractor harvested from
lib `include` globs (`packages/reference-lib/ui.config.ts:19`), resolved
through `unit::css_value_from_authored` (string passthrough) →
`apply_rhythm_and_tokens` (`atomic/src/resolve/mod.rs:324`, pure function
`rhythm::resolve_rhythm`: `140r` → `calc(140 * var(--spacing-root))`) →
emitter (`@layer utilities`: `  .reference-ui__max-w_140r { max-width:
calc(140 * var(--spacing-root)); }`). All primitives funnel through the one
choke point `css()` (`packages/reference-neo/src/runtime/css/css.ts:219`,
bundled pre-registered into `react.mjs` by `packager/react.ts`), whose
`reportStyleMisses` → `reportMissCandidates`
(`atomic/js/namer/miss.ts`, dev microtask probe over live `@layer
utilities` selectors) warns once per miss. So "140r paints nothing" = "namer
constructed a class the sheet never emitted." Any zero-sync fix must either
pre-emit the rule (A), emit it at runtime (B), or bless the miss as a
consumer-toolchain obligation and make it loud (C).

Measured baselines: sheet `packages/reference-lib/.reference-ui/styled/styles.css`
262,040 B / 3,497 lines / ~2,475 utility rules (~75–110 B/rule);
browser artifact `runtime-data.mjs` 87 KB ships `lowerings/prefixes/
breakpoints/colorProps/stylePropNames` but **no** prop→CSS-property map, **no**
unitless table, **no** rhythm resolver, **no** token values
(`contracts/types.ts` `NamerTables`). There is **no** runtime stylesheet
injection anywhere today (no `insertRule`/owned `<style>` in neo runtime or
atomic js). Canon's `to_css_declaration_property` and `is_unitless_prop`
(`modules/canon/src/`) are Rust-only.

## Option A — Continuous-numeric rule generation in the compiler

**What:** lib's own `ref sync` pre-emits rules for a dense numeric sweep
(e.g. integer `0r..400r` × every dimensional prop), so consumer values
inside the sweep hit precompiled rules with zero consumer sync.

**Exact code paths touched:**
- NEW synthesizer sibling to `static_css::append_static_css`
  (`atomic/src/static_css.rs`), called from `AssembleCtx::append_static`
  (`atomic/src/assembly.rs:41`) — pushes `Want{prop, String("Nr")}` before
  `build_atom_set`. Resolve (`resolve_want_with`), naming
  (`stylesheet/name`), and emit work unchanged → rule/class parity with the
  runtime namer by construction (same `rulesVersion`-pinned join that emits
  `max-w_120r` today). `AtomSet` insert dedupes sweep/extraction overlap.
- Config surface: `BaseSystem` gains the sweep spec (or reuse
  `static_css`), TS fragment evaluation + `config/validate.ts`,
  `ui.config.ts` in lib opts in.
- Goldens: `atomic/tests/cases/ATM-STATIC-*` pattern for the new wants;
  sheet-size CI assertion; docs.

**Trade-offs:**
- Bundle: ~30–40 dimensional props (spacing ~22 + size 7 + radius 13 per the
  `is_*_property` predicates in `static_css.rs`) × 401 values ≈ 12–16k
  rules ≈ **+1 MB raw (~4–5× sheet), est. +80–100 KB gz (~3× CSS
  download)** — paid by every consumer even ones using three values.
  Conditions/responsive variants must be excluded (else ×breakpoints×
  conditions → 100k+ rules).
- Correctness: perfect *inside* the sweep (compiler-generated, identical
  layer/cascade). Outside it, unchanged silence.
- Complexity: low (one Rust synthesizer + config plumbing).
- Consumer UX: common integers "just work"; but the cliff moves, it doesn't
  vanish — fractions (`1/3r`), decimals (`0.5r`), negatives, `N > 400`,
  bare numbers, `px`, and conditional values still miss. "139r works but
  401r doesn't" is arguably *more* confusing than today's uniform rule.

**Effort sketch (S–M):** BaseSystem field + TS eval + validate (0.5d);
synthesizer ~150 lines + unit tests (1d); goldens + sheet-size gate (0.5d);
matrix proof (`pnpm agent`, sheet change ships in dist). Gates: `agentrs`
(clippy zero-allow, ≤500-line files, complexity ≤10) + test-core.

**Failure modes:** cliff confusion; sweep prop list drifts from canon (new
dimensional props silently uncovered); theme/token values can't sweep;
sync time grows with +12k wants (resolve is fast — measure, don't assume);
mobile byte budget triples with zero tree-shaking (sheet is monolithic).

## Option B — Runtime fallback declarations for uncompiled numerics

**What:** `css()` detects numeric-resolvable, unconditionally-authored,
non-token declarations and synchronously injects the compiled-equivalent
rule (`.reference-ui__max-w_140r{max-width:calc(140*var(--spacing-root))}`)
into a runtime-owned `<style>` in `@layer utilities` (B1 eager-inject;
track an injected-set, no DOM scan). The existing miss probe then stays
silent naturally (its fingerprint cache invalidates on sheet-count change).
Conditionally-authored, token, and non-numeric values keep the miss path.

**Exact code paths touched:**
- NEW JS port of `resolve_single_rhythm` (`resolve/rhythm/mod.rs:43`, pure,
  ~40 lines) + `resolve_numeric_value` unit policy (`resolve/unit.rs:108`)
  in `atomic/js/namer/` with parity goldens against the Rust tests.
- Artifact extension: `NamerTables::for_system` (`atomic/src/runtime/…`) +
  `contracts/types.ts` must ship prop→CSS-property map (mirror of canon
  `to_css_declaration_property`) and the unitless set (mirror of
  `is_unitless_prop`) — neither is in the browser bundle today; needs a
  `schemaVersion`/`rulesVersion` coordination story across
  `@reference-ui/rust` + neo + packager. Lowering interpretation reuses
  shipped `tables.lowerings` + `interpretLowering` (`lower.ts`); restrict v1
  to keep/identity props to avoid TRBL/trio/macro edge cases. Selector
  escaping via native `CSS.escape`.
- `css.ts:219` integration: after `name()`, for eligible decls
  (`when` empty, string/number value, numeric fence passes), inject + record;
  SSR guard (`typeof document === 'undefined'` → skip).
- Tests: atomic vitest seam parity (JS fallback ≡ Rust resolve on a numeric
  corpus) + neo Playwright cases (`tests/cases/css/NEO-CSS-*`) + matrix
  (browser runtime ships in dist).

**Trade-offs:**
- Bundle: +~3–5 KB runtime JS, artifact +~2–20 KB depending on table scope
  (numeric-props-only vs all props). Zero sheet growth; per-value cost paid
  only when used.
- Correctness: exact for in-scope values *if the ports stay in parity* —
  and that "if" is the whole risk: a second implementation of
  rhythm/unit/css-prop with no consumer-visible pin (naming has
  `rulesVersion`; fallback would need its own). Injected-vs-linked order:
  benign (identical declarations; misses have no competitor by definition).
- Complexity: medium-high — a new runtime subsystem + artifact contract
  change + cross-package version coordination.
- Consumer UX: magic — numerics "just paint", zero toolchain. Debuggability
  cost: the rule lives in a runtime `<style>`, not the shipped CSS.

**Effort sketch (M–L):** artifact extension + version bump (1–2d); JS
fallback module + parity goldens (2–3d); `css.ts` injection manager +
  edge-case hardening (1–2d); neo cases + matrix (1d). Gates: `agentrs q` +
  `agentneo q` (Biome) + test-core.

**Failure modes:** JS/Rust drift (fallback paints X where a synced build
paints Y — silent, consumer-specific); strict CSP (`style-src` blocking the
runtime tag — real consumer risk, needs a documented fallback or nonce
story); SSR unstyled-until-hydration for fallback values; HMR duplicate
tags; scope gaps unchanged (conditions, tokens, arbitrary strings still
miss → still wants W-04); the injected-set grows unboundedly on H-1-style
dynamic values (cap/evict needed).

## Option C — Bless consumer-`sync` as the only path + W-04 loud dev failure

**What:** no new paint path. Keep the documented contract (README already
says it: shipped CSS covers lib values only; app-only values need `ref sync`
+ `extends: [baseSystem]` compiling a consumer sheet) and implement W-04
(`docs/MISSIONS/PLAYTEST-REQUIREMENTS.md:456` — dev-only loud failure naming
prop/value/component; production keeps warn-and-skip; acceptance: `140r`
loud, `120r`/`200r` silent, zero new noise, dev-mode test) so the silence
becomes an actionable toolchain error instead of a mystery.

**Exact code paths touched:**
- `css.ts` `reportStyleMisses` (message already names prop/value/call-site
  via `captureMissSite`; component-name attribution is best-effort stack
  parse — React fiber owner lookup is extra work, flag as optional).
- `miss.ts` `checkCandidates`/`flushPending`: warn → loud. **Must gate on
  sheet completeness / `load`** (reuse `sheetsComplete` + `rearmOnLoad`):
  the H-6 race (Vite-dev-injected `<style>` arrives after first render;
  9 false positives in the smoke run) means a naive synchronous throw would
  crash dev apps on values that *do* compile. Loud-only-after-`load` (or
  `readyState === 'complete'`) keeps W-04 correct at the cost of deferred
  loudness. Reuse the `reportedMissDiagnostics` once-per-value set + a cap:
  H-1-style unbounded dynamic values (drag ticks) would otherwise throw
  forever on distinct values.
- Mechanism choice (spec allows throw OR `console.error` + magenta
  outline): recommend **`console.error`, not throw, not outline** — throw
  is fatal under any residual H-6/H-1 race; the magenta outline is
  infeasible from `css()` (it returns a class string, can't touch the
  element) unless W-04 itself injects a rule for the miss class, which is
  option (B) scoped to a debug declaration (same CSP/SSR caveats for zero
  paint benefit). `console.error` naming prop/value/site is loud,
  non-fatal, race-tolerant, and zero-injection.
- Consumer-sync side: already exists (`defineConfig` include globs +
  `extends`, `base-system` merge in `modules/base-system/src/extends/`);
  work is docs polish + a consumer-sync onboarding test, not features.
- Tests: neo dev-mode case (miss → error, hit → silent) + H-6 regression
  (early-batch → silent until load, then verdict).

**Trade-offs:**
- Bundle: zero. Correctness: perfect by construction (only compiled values
  paint; everything else is loud in dev, warn-and-skip in prod).
- Complexity: low (one runtime file pair + tests).
- Consumer UX: honest but demanding — custom values require adopting the
  `ref sync` toolchain (binary, config, build step) instead of "import
  CSS and go". Two-tier story, but it's the story the README already tells.

**Effort sketch (S):** `miss.ts` loudness + load gating (0.5–1d);
message/attribution polish (0.5d); neo cases incl. H-6 regression (0.5–1d);
docs touch-up (0.5d). Depends on H-6 disposition (fix or load-gate
semantics). Gates: `agentneo` (+ `agentrs` for the touched `miss.ts`).

**Failure modes:** consumers ignore `console.error`; weak component
attribution (stack-only); load-gated loudness fires late for
post-load-mounted misses (still fires — every post-load batch checks
immediately); sync-tooling adoption friction for small consumers; does not
paint anything new (by design).

---

## Ranking and recommendation

1. **(C) Bless consumer-sync + W-04 (`console.error`, load-gated) — DO NOW.**
   Zero bytes, zero new failure classes, smallest correct change; directly
   implements the ACCEPTed W-04 requirement; the toolchain path it blesses
   already exists and is already documented. Its two subtleties (H-6
   load-gating, no-throw mechanism) are handled above.
2. **(B) Runtime fallback for unconditional numerics — DO NEXT IF HQ wants
   the magic.** The only option that literally achieves "arbitrary consumer
   numerics paint with zero sync" (within numeric scope). Bounded, shippable
   v1 (unconditional + string/number + rhythm/unit/css-prop ports + artifact
   tables), but buys permanent dual-implementation parity maintenance plus
   CSP/SSR caveats. Do not attempt without the artifact versioning story.
3. **(A) Compiler numeric sweep — DO NOT.** Dominated on both sides: pays
   ~1 MB raw / ~3× gz for *partial* coverage while keeping a cliff (and a
   more confusing one), and still needs W-04 for everything past the bound.
   Only defensible as a time-boxed stopgap if (B) is rejected and HQ wants
   common integer cases zero-sync-painting this week — say so explicitly if
   choosing it.

Cross-cutting: **W-04 is needed under all three options** (A and B both
leave out-of-scope value classes silent: conditions/tokens/arbitrary strings
under B; everything past the sweep under A). H-6 (dev probe race) must be
fixed-or-gated before any loud-failure mechanism lands, or dev breaks on
false positives.
