## 2. Blocker (precise)

- **Required by T17** (G1 §4 + this brief): the consumer's loaded sheet carries
  `reference-icons__c_<probe-stem>`, i.e. `reference-icons` is one of the
  composed-system qualifiers the external want fans out to.
- **Landed engine**: `packages/reference-neo/src/sync/index.ts:156` derives
  `upstreamSystems = deduped([...extends, ...layers].map(s => s.name).filter(n => n !== spec.name))`
  (T06 / G0 C13, frozen verbatim). For T17's config (extends lib, layers
  fixture) that yields `["reference-ui","aliased-host-library"]`. `reference-icons`
  exists only as a **nested stream** inside lib's `BaseSystem.streams`, never as
  a direct `.name`, so it never becomes a qualifier.
- **Consequence**: the consumer emits the icon probe classes under
  `reference-ui__`/`aliased-host-library__` only. The icons runtime mints
  `reference-icons__c_t17ProbeInk`, which no sheet backs → the icon faints, the
  runtime warns `no compiled class`, and the four probe icons are unbacked.
- **Why the transitive reach is required, not optional**: `STYLE_PROP_EXTERNAL`
  §1's motivating case is docs styling `<BoltIcon color=…>` where docs
  `extends` lib and icons arrive **transitively**. `BaseSystem.streams` is
  documented as "transitively expanded" (`system/base/types.ts:32`), and the
  existing `hasUpstreamContainerRoot` already scans `.streams` for the same
  transitive reach (`system/base/container-root.ts:40`). `.name`-only is the
  outlier.
- **Not fixable test-side**: this is not a T17 config gap. Directly listing the
  icons baseSystem as an extra upstream makes the probe rule appear but prints
  the icons canonical 7 **twice** (lib already carries the nested icons stream),
  which fails the G1 §4 "duplicates in neither" accounting. Measured: layering
  icons gave `reference-icons__ai_center ×2`, `…c_inherit ×2`, all 7 doubled.
  So the qualifier must arrive transitively.

## 6. Verified fix (recommended — NOT landed; engine-owned, T06/C13)

`packages/reference-neo/src/sync/index.ts` (`evaluateAndCompile`): derive the
qualifier names from each upstream's transitively-expanded `streams`, falling
back to `.name` when absent (older/hand-authored baseSystems):

```ts
const upstreamSystems = deduped(
  [...(config.extends ?? []), ...(config.layers ?? [])]
    .flatMap((system) =>
      system.streams && system.streams.length > 0
        ? system.streams.map((stream) => stream.name)
        : [system.name]
    )
    .filter((name) => name !== spec.name)
)
```

- T17: `["reference-icons","reference-ui","aliased-host-library"]` → 14/14 green (§4f).
- Byte-identity: no-upstream worlds have no `streams` → fallback `.name` →
  unchanged; T16 (nested icons, but no external wants) unchanged (6/6, §4d).
- Consistency: mirrors `hasUpstreamContainerRoot`'s `.streams` scan
  (`system/base/container-root.ts:40`). `BaseSystem.streams` is already
  transitively expanded (`system/base/types.ts:32`).
- Requires the neo decisive suite (`pnpm agentneo q src/sync/index.ts`,
  `NEO-SYNC-04`, `NEO-SYNC-06`) before landing — SYNC-04/06 are no-upstream,
  so the key-absent byte-diff is preserved.

Until this lands, `pnpm agent test --packages=@matrix/chain-t17` is red by
construction, and `NEO-CHAIN-08`/docs-tone fan-out (T10) cannot be green either.
