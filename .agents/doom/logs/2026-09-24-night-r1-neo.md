# Sync error throws drop the stable code

## Hypothesis

Gap pursued: the error presentation path in Neo diagnostics mints a
partial refusal — message plus location, no code. The engine returns
`ATM-E-*` rows in-band with stable codes (`NativeCompileResult.diagnostics`),
the transport validates them, and the repro suites pin every error code with
its severity through real compiles — but the single user-facing error surface,
`throwOnErrorDiagnostics` (`packages/reference-neo/src/diagnostics/report.ts:19-24`),
formats each line as ``- ${message} (${file}:${line}:${column})`` with no code
segment. Warnings ride verbose lines as `code: message` with hints; errors
throw codeless. There is no alternate error surface: `reportSyncDiagnostics`
prints warnings only, `reportedSyncEntries` drops userspace errors from the
`--json` set, and every CLI failure line (`[ref] sync failed: …`, `[ref] watch
error: …`) prints `messageOf(err)` from this same throw, so `--json` failures
carry the codeless cause on stderr with empty stdout. Error censuses by
`rg -c` — the module's own stated method — return zero hits by construction.

The red test (`/tmp/doom-r1-neo-red.mjs`, blind-runnable via repo tsx)
compiles a real bad-token world through real `compileWorld`, asserts the
engine minted coded errors, calls the real `throwOnErrorDiagnostics`, and
asserts the throw names each minted code. Today: engine mints
`ATM-E-UNKNOWN-TOKEN`, throw reads `native compile failed:\n- unknown token
reference \`{colors.nope}\` (…/theme/bad.ts:3:33)` — 0 of 1 codes named,
exit 1. The throw shape is pinned nowhere (no test asserts it), so the
omission is oversight, not design; the sibling native layers throw coded
(`TST-E-SCAN-FAILED`, `STT-E-*`, `TGN-E-*` repro tests assert the code in the
throw), making Neo's sync throw the lone exception.

Reconciliation work that came back clean (not pursued as theories): the
`WARNING_HINTS` table covers every live warning code in the Rust codes tables
plus the retired `ATM-W-TOKEN-CATEGORY-MISMATCH` (kept for wire stability per
the registry); registry, repro rows, and request-level repros agree on all
`ATM`/`ATL`/`TST`/`STT`/`TGN` codes; verbose-list `×N` sums reconcile with the
one-liner and boot-block counts on every path (one-shot, watch baseline,
watch resync, fold/ref-drain). Carried but unspent: dedupe key (severity,
span, labels, help) is finer than the verbose presentation identity
(channel, file, line, column, code, message), so rows differing only in
unprinted fields would render as duplicate lines with no `×N` — no natural
engine trigger found (engine sends span+line+column together, no labels/help
observed); and compiler-channel `info` telemetry counts into the one-liner's
"warnings" noun — pinned-loose by an exact-count-avoiding test, likely
accepted.

## Verdict

`break-found`. Repro: `/tmp/doom-r1-neo-red.mjs` (run:
`packages/reference-neo/node_modules/.bin/tsx /tmp/doom-r1-neo-red.mjs` from
the repo root; exits 1 on the red assertion, writes nothing to the tree).

Violated contract:

- `REGISTRY.md` ("A code is always present, always documented, and always
  traceable here — that traceability is the whole return on the diagnostics
  platform"): error codes never reach any user surface.
- `report.ts` census contract ("The stable codes ride the verbose lines so
  censuses count by `rg -c`, not by prose"): errors ride no verbose lines and
  throw without codes, so error censuses must count by prose.
- Module README ("Every error code earns one repro test … asserts the code
  with its severity"): the platform mints, validates, and tests codes its
  sole error presentation then drops — partial mint.

Severity: user-facing. Every failed sync across every author hides the
failure class; authors and agents debugging `ATM-E-*` refusals must match
prose instead of codes, and identical prose across distinct failure classes
is indistinguishable. In-bounds: complete static literal in a TS compile
input; silence where a diagnostic code is owed, not a will-never-work shape.
