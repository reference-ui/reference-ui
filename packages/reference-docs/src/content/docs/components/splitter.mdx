# Splitter

Splitter divides a container into resizable panels along a horizontal or
vertical axis. Users can resize panels by dragging the handle between them or
using the arrow keys.

<Preview>
  <SplitterDemo />
</Preview>

```tsx
import { useState } from 'react'
import { Splitter } from '@reference-ui/lib'

export function Layout() {
  const [sizes, setSizes] = useState([40, 60])
  return (
    <Splitter value={sizes} onChange={setSizes}>
      <Splitter.Panel min="20r">Sidebar</Splitter.Panel>
      <Splitter.Handle aria-label="Resize sidebar" />
      <Splitter.Panel>Main</Splitter.Panel>
    </Splitter>
  )
}
```

## Import

```tsx
import { Splitter } from '@reference-ui/lib'
```

## Anatomy

```tsx
<Splitter>
  <Splitter.Panel />
  <Splitter.Handle>
    <Splitter.Thumb />
  </Splitter.Handle>
  <Splitter.Panel />
</Splitter>
```

`Splitter` requires alternating `Splitter.Panel` and `Splitter.Handle`
children, starting and ending with a `Splitter.Panel` (at least two panels).
`value` must contain one percentage entry per panel, summing to `100`; invalid
child order or mismatched array lengths throw a descriptive error.

`Splitter` is a controlled component: pass the array of panel percentages to
`value` and update it via `onChange`.

## Examples

### Size limits

Use `min` and `max` to constrain a panel's size. Numbers represent percentages
of the available panel space, while strings accept CSS lengths (`px`, `rem`,
`em`, `r`, or `%`), measured against total container space excluding handle
widths.

```tsx
<Splitter.Panel min="60r" max={50}>Sidebar</Splitter.Panel>
```

When `min` is omitted, panels default to a minimum size of `5%`.

### Collapsible panels

Set `collapsible` on a `Splitter.Panel` to allow it to collapse to
`collapsedSize` (`0` by default) when dragged more than halfway past its `min`
threshold. Pressing `Enter` on a focused `Splitter.Handle` toggles the
preceding collapsible panel between its collapsed state and its previous size.

### Vertical and nested

Set `orientation="vertical"` to stack panels vertically. Nest a vertical
`Splitter` inside a horizontal `Splitter.Panel` to create a two-dimensional
split layout.

<Preview>
  <SplitterNestedDemo />
</Preview>

```tsx
<Splitter value={columns} onChange={setColumns}>
  <Splitter.Panel min={20} collapsible>Sidebar</Splitter.Panel>
  <Splitter.Handle aria-label="Resize sidebar" />
  <Splitter.Panel>
    <Splitter orientation="vertical" value={rows} onChange={setRows}>
      <Splitter.Panel min="10r">Editor</Splitter.Panel>
      <Splitter.Handle aria-label="Resize console" />
      <Splitter.Panel min="10r">Console</Splitter.Panel>
    </Splitter>
  </Splitter.Panel>
</Splitter>
```

### Saving the layout

`onChange` fires continuously during resizing, while `onChangeEnd` fires once
with the final sizes when the pointer or key is released. Use `onChangeEnd` to
persist panel sizes.

```tsx
<Splitter
  value={sizes}
  onChange={setSizes}
  onChangeEnd={(next) => localStorage.setItem('layout', JSON.stringify(next))}
>
  <Splitter.Panel>Sidebar</Splitter.Panel>
  <Splitter.Handle aria-label="Resize sidebar" />
  <Splitter.Panel>Main</Splitter.Panel>
</Splitter>
```

Updating `value` programmatically does not trigger `onChange` or `onChangeEnd`.

### Reading sizes in CSS

Each Panel sets `--reference-splitter-panel-size` to its own size. The root
sets `--reference-splitter-1` through `--reference-splitter-N` (one per
Panel in order) so child styles can reference panel sizes.

## API reference

### Splitter

The root flex container that arranges panels and handles along the configured
axis. Renders a `div`.

<Reference name="SplitterProps" headingLevel={4} />

| Attribute | Values |
| --- | --- |
| `[data-orientation]` | `horizontal`, `vertical` |
| `[data-resizing]` | Present while a Handle is dragged. |

### Splitter.Panel

A resizable panel region. Renders a scrollable `div`.

<Reference name="SplitterPanelProps" headingLevel={4} />

| Attribute | Values |
| --- | --- |
| `[data-orientation]` | `horizontal`, `vertical` |
| `[data-collapsed]` | Present while a collapsible Panel is at its collapsed size. |
| `[data-resizing]` | Present while any Handle in the group is dragged. |

### Splitter.Handle

The draggable separator between two adjacent panels. Renders a focusable `div`
containing a divider line and `Splitter.Thumb` by default, or custom children
if provided.

<Reference name="SplitterHandleProps" headingLevel={4} />

| Attribute | Values |
| --- | --- |
| `[data-orientation]` | `horizontal`, `vertical` |
| `[data-state]` | `idle`, `hover`, `active` |
| `[data-hover]` | Present while hovered. |
| `[data-resizing]` | Present while this Handle is dragged. |
| `[data-disabled]` | Present when `disabled`. |

### Splitter.Thumb

The visual grip centered inside `Splitter.Handle`, visible when the handle is
hovered, focused, or actively dragged.

<Reference name="SplitterThumbProps" headingLevel={4} />

| Attribute | Values |
| --- | --- |
| `[data-state]` | `idle`, `hover`, `active` |
| `[data-disabled]` | Present when the Handle is `disabled`. |

## Accessibility

Splitter follows the [WAI-ARIA Window Splitter pattern](https://www.w3.org/WAI/ARIA/apg/patterns/windowsplitter/).

Each `Splitter.Handle` renders with `role="separator"` and reports the current
size of the preceding panel via `aria-valuenow`. Provide an `aria-label` on
every handle.

### Keyboard interactions

| Key | Description |
| --- | --- |
| `ArrowLeft` / `ArrowRight` | In a horizontal Splitter, moves the focused Handle by 1%. |
| `ArrowUp` / `ArrowDown` | In a vertical Splitter, moves the focused Handle by 1%. |
| `Shift` + arrow | Moves the Handle by 10%. |
| `Home` | Collapses or shrinks the preceding panel to its minimum allowed size. |
| `End` | Expands the preceding panel to its maximum allowed size. |
| `Enter` | Collapses or restores the Panel before the Handle, when it is `collapsible`. |

In right-to-left layouts, the horizontal arrow keys are reversed.
