# Presence

Presence delays unmounting its child when `present` becomes `false` until any
exit CSS animation, transition, or GSAP tween completes.

<Preview>
  <PresenceDemo />
</Preview>

```tsx
import { Div, css } from '@reference-ui/react'
import { Presence } from '@reference-ui/lib'

const fade = css({
  transition: 'opacity 0.3s ease',
  '&[data-state="closed"]': { opacity: '0' },
})

<Presence present={open}>
  <Div data-state={open ? 'open' : 'closed'} className={fade}>
    Fades before it leaves the DOM.
  </Div>
</Presence>
```

Presence does not set `data-state` itself; set a state attribute or class on
the child to trigger your exit styles when `present` is `false`.
[Overlay](/overlay), [Popover](/popover), and [Collapsible](/collapsible)
already include Presence internally, so do not wrap them in another Presence.

## Behaviour

- Presence observes CSS animations, CSS transitions, and finite GSAP tweens on
  the direct child element only; animations on nested descendants are not
  tracked.
- A CSS keyframe animation delays unmounting only when `animation-name`
  changes as `present` becomes `false`. Infinite animations are ignored.
- If no exit animation or transition is detected (including when
  `prefers-reduced-motion` disables transitions, the element has
  `display: none`, or the browser tab is hidden), the child unmounts
  immediately.
- Setting `present` back to `true` while an exit animation is running cancels
  the exit: the child remains mounted and `onExitComplete` is not called.
- Nested `Presence` components coordinate automatically so inner exit
  animations complete before the outer `Presence` unmounts.
- Presence manages exit unmounting only; define enter animations directly in
  CSS.
- Presence renders no wrapper element. It throws an error if `children` is not
  a single React element, or if the child does not forward its `ref` to a DOM
  node when closing.
