# Portal

Portal renders its children into a separate DOM node (`document.body` by
default) while preserving their position in the React component tree.

<Preview>
  <PortalDemo />
</Preview>

```tsx
import { Div } from '@reference-ui/react'
import { Portal } from '@reference-ui/lib'

<Portal>
  <Div position="fixed" bottom="4r" right="4r">Saved</Div>
</Portal>
```

Portal only relocates DOM output: it adds no wrapper element and does not
manage stacking, focus trapping, or dismissal. [Overlay](/overlay),
[Popover](/popover), and [Tooltip](/tooltip) already portal their content
automatically; use Portal when building custom floating layers.

## Import

```tsx
import { Portal } from '@reference-ui/lib'
```

## Examples

### Custom container

Pass `container` to mount children into a specific DOM node instead of
`document.body`. You can pass a React ref even if the target element mounts
after the Portal.

```tsx
const destination = useRef<HTMLDivElement>(null)

<>
  <Portal container={destination}>
    <Div>Rendered through a portal.</Div>
  </Portal>
  <Div ref={destination} />
</>
```

Inside an Overlay, set the container with
[`Overlay.Portal`](/overlay#overlayportal) instead.

## Behaviour

- Portal renders nothing during server rendering or the initial client render;
  children mount after hydration completes.
- If `container` is a ref or getter function that resolves to `null`, Portal
  renders nothing until a DOM node is available.
- Changing `container` remounts the children into the new target node, which
  resets their local DOM and component state.
- React context and synthetic event bubbling follow the React component tree
  rather than the DOM hierarchy.
- The outermost Reference UI element inside a portal inherits the active color
  mode, preserving light or dark theme tokens.
