# Portal

By default the children render at the end of `document.body`. In the React
tree they stay where you wrote them.

<Preview>
  <PortalDemo />
</Preview>

```tsx
import { Div } from '@reference-ui/react'
import { Portal } from '@reference-ui/lib'

<Portal>
  <Div position="fixed" bottom="4r" right="4r">Saved</Div>
</Portal>
```

Portal only moves content. It adds no wrapper element and handles no
stacking, focus or dismissal. [Overlay](/overlay), [Popover](/popover) and
[Tooltip](/tooltip) already portal their content; use Portal for your own
layers.

## Import

```tsx
import { Portal } from '@reference-ui/lib'
```

## Examples

### Custom container

Pass `container` to render somewhere other than `document.body`. A ref works
even when its element mounts after the Portal.

```tsx
const destination = useRef<HTMLDivElement>(null)

<>
  <Portal container={destination}>
    <Div>Rendered through a portal.</Div>
  </Portal>
  <Div ref={destination} />
</>
```

Inside an Overlay, set the container with
[`Overlay.Portal`](/overlay#overlayportal) instead.

## Behaviour

- Portal renders nothing on the server or on the first client render. The
  children appear once it has mounted.
- A ref or function that returns `null` renders nothing until it returns a
  node.
- Changing `container` moves the children to the new node. Don't rely on
  their local state surviving the move.
- React context and events follow the React tree, not the DOM position.
- The first Reference UI element inside the portal reapplies the color mode,
  so portalled content keeps light or dark mode.
