# FocusLock

FocusLock traps keyboard focus inside a container element. Pressing Tab cycles
through tabbable elements inside the lock, and focus returns to the previously
focused element when the lock is deactivated.

<Preview>
  <FocusLockDemo />
</Preview>

```tsx
import { Div } from '@reference-ui/react'
import { FocusLock } from '@reference-ui/lib'

<FocusLock>
  <Div role="dialog" aria-modal="true" aria-label="Settings">
    {children}
  </Div>
</FocusLock>
```

[Overlay](/overlay) already includes FocusLock when modal isolation is
enabled. Use FocusLock directly when building custom modal containers.

## Import

```tsx
import { FocusLock } from '@reference-ui/lib'
```

## Props

FocusLock accepts a single React element child and renders no wrapper element.
Any `ref` passed to FocusLock is forwarded to that child.

<Reference name="FocusLockProps" headingLevel={3} />

A `FocusTarget` is an element, a ref to one, or a function that returns one.

## Behaviour

- When the lock activates, focus moves to `initialFocus` if specified and
  contained within the lock. If focus is already inside the container, it
  remains on the current element; otherwise it moves to the first tabbable
  element, or to the container itself if no tabbable descendants exist.
- Unmodified `Tab` and `Shift+Tab` presses wrap at the start and end of the
  container. If focus moves outside the container programmatically, FocusLock
  restores it inside.
- When FocusLock unmounts or `disabled` becomes `true`, focus returns to the
  element that held focus before the lock activated (or to `returnFocus` if
  provided). If that element has been removed from the DOM, focus moves to the
  nearest remaining focusable sibling or ancestor.
- When multiple FocusLocks are mounted, only the most recently activated lock
  is active; outer locks pause until the inner lock deactivates.
- FocusLock manages focus only. For `Escape` dismissal, outside pointer
  clicks, background `inert` handling, and scroll locking, use
  [Overlay](/overlay).

## Accessibility

FocusLock moves focus but adds no roles or labels. Give the child a role such
as `dialog` and an accessible name.

| Key | Description |
| --- | --- |
| `Tab` | Moves to the next tabbable element in the lock, wrapping from last to first. |
| `Shift + Tab` | Moves to the previous tabbable element, wrapping from first to last. |

For arrow-key movement inside a widget, use [RovingFocus](/roving-focus).
