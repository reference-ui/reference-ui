# FocusLock

FocusLock keeps keyboard focus inside one element. Tab cycles within it, and
focus returns to where it was when the lock ends.

<Preview>
  <FocusLockDemo />
</Preview>

```tsx
import { Div } from '@reference-ui/react'
import { FocusLock } from '@reference-ui/lib'

<FocusLock>
  <Div role="dialog" aria-modal="true" aria-label="Settings">
    {children}
  </Div>
</FocusLock>
```

[Overlay](/overlay) locks focus for you when it isolates a dialog. Use
FocusLock directly for containers you build yourself.

## Import

```tsx
import { FocusLock } from '@reference-ui/lib'
```

## Props

FocusLock takes one element child and adds no wrapper. A `ref` passes through
to that child.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `disabled` | `boolean` | `false` | Turns the lock off. |
| `initialFocus` | `FocusTarget \| boolean` | first tabbable | Where focus goes when the lock starts. `false` leaves focus where it is. |
| `restoreFocus` | `FocusTarget \| boolean` | `true` | Where focus goes when the lock ends. `false` leaves it. |
| `defaultRestoreTarget` | `FocusTarget` | — | Where focus returns if nothing outside the lock had focus when it started. |
| `shards` | `Array<HTMLElement \| RefObject>` | — | Elements outside the child that belong to the lock, such as a portalled popover. |

A `FocusTarget` is an element, a ref to one, or a function that returns one.

## Behaviour

- On start, focus moves to `initialFocus` if it is inside the lock. If focus
  is already inside, it stays. Otherwise the first tabbable element gets it,
  or the child itself when nothing inside is tabbable.
- Only Tab and Shift+Tab without modifier keys loop. Focus moved outside by
  script is pulled back.
- The lock ends when it unmounts or `disabled` turns on. Focus then returns to the element that had it before. If that element is
  gone, focus goes to its nearest remaining neighbour.
- When locks nest, the most recent one wins. The one below pauses until it
  ends.
- FocusLock does not handle Escape, outside clicks, inert backgrounds or
  scroll locking. [Overlay](/overlay) does.

## Accessibility

FocusLock moves focus but adds no roles or labels. Give the child a role such
as `dialog` and an accessible name.

| Key | Description |
| --- | --- |
| `Tab` | Moves to the next tabbable element in the lock, wrapping from last to first. |
| `Shift + Tab` | Moves to the previous tabbable element, wrapping from first to last. |

For arrow-key movement inside a widget, use [RovingFocus](/roving-focus).
