# Calendar

Calendar is a month grid for picking a date, a date range, a month or a
year. Values are ISO strings, never `Date` objects.

<Preview>
  <CalendarDemo />
</Preview>

```tsx
import { useState } from 'react'
import { Calendar, type ISODate } from '@reference-ui/lib'

export function DueDate() {
  const [date, setDate] = useState<ISODate | null>(null)
  return <Calendar value={date} onChange={setDate} locale="en-GB" />
}
```

Calendar does not parse typed dates. For a text input, use
[DateField](/date-field).

## Import

```tsx
import {
  Calendar,
  type DateRangeValue,
  type ISODate,
  type ISOMonth,
  type ISOYear,
} from '@reference-ui/lib'
```

## Anatomy

```tsx
<Calendar>
  <Calendar.Header>
    <Calendar.PrevButton />
    <Calendar.Heading>
      <Calendar.Month />
      <Calendar.Year />
    </Calendar.Heading>
    <Calendar.NextButton />
  </Calendar.Header>
  <Calendar.Grid>
    <Calendar.Weekdays />
    <Calendar.Days>
      {(day) => <Calendar.Day date={day.date}>{day.formattedDay}</Calendar.Day>}
    </Calendar.Days>
  </Calendar.Grid>
  <Calendar.Months />
  <Calendar.Years />
</Calendar>
```

Without children, Calendar renders this structure. Author a part to replace
its default; the parts you leave out keep theirs.

The grid, the months and the years are three views of one calendar, and one
shows at a time. Pressing `Calendar.Month` or `Calendar.Year` in the header
switches to that view. Picking a month or year there moves the grid and
switches back.

## Examples

### Range

Set `mode="range"`. The first click sets the start, and the second sets the
end. Clicking a date before the start swaps the two.

<Preview>
  <CalendarRangeDemo />
</Preview>

```tsx
const [stay, setStay] = useState<DateRangeValue | null>(null)

<Calendar mode="range" value={stay} onChange={setStay} locale="en-GB" />
```

After the first click the value is `{ start, end: null }`. While the end is
open, hovering or focusing a day previews the range. A range that would
include an unavailable date is refused, and the start stays.

### Month or year

`mode="month"` picks a `'YYYY-MM'` month and `mode="year"` a `'YYYY'` year.
Calendar opens on the months or years view.

```tsx
const [month, setMonth] = useState<ISOMonth | null>(null)

<Calendar mode="month" value={month} onChange={setMonth} locale="en-GB" />
```

### Limits

`min` and `max` disable the dates outside them. `isDateUnavailable` blocks
single dates.

```tsx
const isWeekend = (date: ISODate) => [0, 6].includes(new Date(date).getUTCDay())

<Calendar
  value={date}
  onChange={setDate}
  locale="en-GB"
  min="2026-01-01"
  max="2026-12-31"
  isDateUnavailable={isWeekend}
/>
```

A date outside `min` and `max` is disabled and skipped by the arrow keys. An
unavailable date can still be focused, but it can't be selected.

### Custom days

`Calendar.Days` takes a function that is called for each date with its
state. It must return one `Calendar.Day` with the same `date`. Selection,
focus and ARIA stay with Calendar.

```tsx
<Calendar value={date} onChange={setDate} locale="en-GB">
  <Calendar.Grid>
    <Calendar.Days>
      {(day) => (
        <Calendar.Day date={day.date}>
          {day.formattedDay}
          {holidays.has(day.date) ? ' •' : null}
        </Calendar.Day>
      )}
    </Calendar.Days>
  </Calendar.Grid>
</Calendar>
```

To change only the content of each day, pass the `Day` prop instead:
`Day={(date, state) => node}`. Return `null` to keep the day number.

### Server rendering

Calendar marks today with the browser's date after it mounts, so the server
renders no marker. Pass `today` to render the same month and marker
everywhere:

```tsx
<Calendar value={date} onChange={setDate} locale="en-GB" today="2026-10-17" />
```

## API reference

### Calendar

Contains the parts. Renders a `div` and takes its props and style props.

<Reference name="CalendarSharedProps" />

Three more props depend on `mode`. `mode` picks what a selection chooses and
defaults to `'day'`. `value` is required: it is the controlled value, and
`null` is empty. `onChange` is called with the picked value.

| Mode | `value` type | Format |
| --- | --- | --- |
| `day` | `ISODate \| null` | `'2026-10-17'` |
| `range` | `DateRangeValue \| null` | `{ start: '2026-10-17', end: '2026-10-20' }`; `end` is `null` until picked. |
| `month` | `ISOMonth \| null` | `'2026-10'` |
| `year` | `ISOYear \| null` | `'2026'` |

`onChange` is never called with `null`, and picking the current value again
does not call it. Without `month`, the visible month follows `value`, then
`today`, then the current month. With `month`, Calendar only calls
`onMonthChange` and you move the month.

An invalid prop, such as a malformed date, a missing `locale` or `min`
after `max`, renders nothing and logs one warning in development.

| Data attribute | Values |
| --- | --- |
| `[data-mode]` | `day`, `range`, `month`, `year` |
| `[data-view]` | `day`, `month`, `year` |

### Header parts

| Part | Renders | Description |
| --- | --- | --- |
| `Calendar.Header` | `div` | The row above the grid. |
| `Calendar.PrevButton` | `button` | Moves to the previous month. Its label names that month. Defaults to `‹`. |
| `Calendar.NextButton` | `button` | Moves to the next month. Defaults to `›`. |
| `Calendar.Heading` | `div` | The visible month and year. Children replace the text. |
| `Calendar.Month` | `button` | Shows the months view. Pressed while it is open. |
| `Calendar.Year` | `button` | Shows the years view. Pressed while it is open. |

The previous and next buttons are disabled outside the days view, and when
the month they lead to has no selectable date.

### Calendar.Grid

The day table. Renders a `table` with `role="grid"`, labelled by the
heading unless you pass `aria-label` or `aria-labelledby`. Its children can
only be `Calendar.Weekdays` and `Calendar.Days`.

### Calendar.Weekdays

The weekday names, ordered by the locale. Renders a `thead` and takes no
children.

### Calendar.Day

One day. Renders a `button`.

<Reference name="CalendarDayProps" />

Your styles, event handlers and ref apply. Calendar keeps `id`,
`tabIndex`, `disabled` and the ARIA attributes.

| Data attribute | Present when |
| --- | --- |
| `[data-date]` | Always. Holds the ISO date. |
| `[data-selected]` | The date is selected. |
| `[data-in-range]` | Inside a selected range. |
| `[data-range-start]` | First date of a range. |
| `[data-range-end]` | Last date of a range. |
| `[data-outside-month]` | The date belongs to the previous or next month. |
| `[data-today]` | The date is today. |
| `[data-disabled]` | Outside `min` and `max`. |
| `[data-unavailable]` | Refused by `isDateUnavailable`. |
| `[data-focused]` | The day that takes focus in the grid. |

### Calendar.Months

Twelve month buttons in three columns. Renders a `div`. In `day` and `range`
mode a month moves the grid; in `month` mode it is the value.

### Calendar.Years

Year buttons in three columns. Renders a `div`. It lists ten years on each
side of the visible year, or the years from `min` to `max` when both are
set.

## Accessibility

The grid is labelled by the heading, and screen readers announce the new
month after navigation. Each day button is labelled with its full date.

Only one day is in the tab order. Moving with the keyboard changes focus and,
when needed, the month. It never changes the value.

### Keyboard interactions

In the days view:

| Key | Action |
| --- | --- |
| `ArrowLeft` / `ArrowRight` | Moves to the previous or next day. Reversed in a right-to-left `dir`. |
| `ArrowUp` / `ArrowDown` | Moves to the same weekday in the previous or next week. |
| `Home` / `End` | Moves to the first or last day of the week. |
| `PageUp` / `PageDown` | Moves to the same day in the previous or next month. |
| `Enter` / `Space` | Selects the focused day. |
| `Tab` | In `range` mode with a start picked, completes the previewed range, then leaves the grid. |

The arrow keys skip dates outside `min` and `max`.

In the months and years views, `ArrowLeft` and `ArrowRight` move one cell,
`ArrowUp` and `ArrowDown` move one row, and `Enter` or `Space` presses the
focused cell.
