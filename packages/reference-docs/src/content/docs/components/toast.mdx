# Toast

Toast displays a temporary notification in a corner of the viewport that
automatically dismisses after a timeout.

<Preview>
  <ToastDemo />
</Preview>

```tsx
import { Button } from '@reference-ui/react'
import { toast } from '@reference-ui/lib'

<Button onClick={() => toast('Changes saved', { description: 'Your settings were updated.' })}>
  Show toast
</Button>
```

Toasts are rendered by [ReferenceLibrary](/reference-library). Mount
`ReferenceLibrary` once near your application root; before it mounts, `toast()`
calls are queued and displayed once the provider is ready.

## Import

```tsx
import { Toast, toast } from '@reference-ui/lib'
```

Use `toast` to trigger notifications, and `Toast` to compose custom toast
layouts.

## Anatomy

Toasts are triggered imperatively with `toast()`, which renders the default
notification layout. To render custom markup, pass a render function to
`toast.custom()` and compose the `Toast.*` parts.

```tsx
toast.custom(() => (
  <Toast.Root>
    <Toast.Title />
    <Toast.Description />
    <Toast.Action />
    <Toast.Cancel />
    <Toast.Close />
  </Toast.Root>
))
```

## Examples

### Types

Use `toast.success`, `toast.error`, `toast.warning`, and `toast.info` to
display a toast with a corresponding status icon.

```tsx
toast.success('Invite sent')
toast.error('Upload failed')
toast.warning('Storage almost full')
toast.info('A new version is available')
```

### Action and cancel

`action` and `cancel` take a label and a click handler. Both dismiss the
toast after the click unless the handler calls `event.preventDefault()`.

```tsx
toast('File deleted', {
  action: { label: 'Undo', onClick: () => restore(file) },
})
```

### Promise

`toast.promise` displays a loading toast and updates it in place when the
promise resolves or rejects. `success` and `error` accept either static content
or a function receiving the resolved value or error. Once settled, the toast
auto-dismisses after 4 seconds.

```tsx
toast.promise(saveReport(), {
  loading: 'Saving report',
  success: report => `${report.name} saved`,
  error: 'Could not save the report',
})
```

### Updating a toast

Every `toast` call returns the toast's ID. Pass that ID to `toast.update` to
update an existing toast in place, or pass a custom `id` in options to
deduplicate or replace a toast.

```tsx
const id = toast.loading('Uploading')
// later
toast.update(id, 'Upload complete', { type: 'success', duration: 3000 })
```

Loading toasts do not auto-dismiss and remain visible until updated or
explicitly dismissed.

### Custom toasts

`toast.custom` accepts a render function that receives the toast ID. Inside it,
`Toast.*` subcomponents automatically connect to the current toast context so
`Toast.Close` and `Toast.Action` dismiss that instance.

```tsx
toast.custom(id => (
  <Toast.Root>
    <Toast.Title>Draft saved</Toast.Title>
    <Toast.Description>Saved to your workspace.</Toast.Description>
    <Toast.Action onClick={() => openDraft(id)}>Open</Toast.Action>
    <Toast.Close />
  </Toast.Root>
))
```

### Defined toasts

`toast.define` creates a typed, reusable toast factory. Call the returned
function with your custom props to display the toast; its `render` callback
receives those props along with `{ close }` to dismiss the instance.

```tsx
const ProjectSaved = toast.define<{ name: string }>({
  duration: 4000,
  render: ({ name }, { close }) => (
    <Toast.Root>
      <Toast.Title>{name} was saved</Toast.Title>
      <Button onClick={close}>Dismiss</Button>
    </Toast.Root>
  ),
})

const id = ProjectSaved({ name: 'Atlas' }, { announce: 'Atlas was saved' })
ProjectSaved.update(id, { name: 'Atlas v2' })
```

### Parts

| Part | Renders | Description |
| --- | --- | --- |
| `Toast.Root` | `div` | The card. Takes `unstyled`. |
| `Toast.Title` | `div` | The headline. |
| `Toast.Description` | `div` | Secondary text. |
| `Toast.Action` | `button` | Primary button. Dismisses its toast after `onClick`. |
| `Toast.Cancel` | `button` | Secondary button. Dismisses its toast after `onClick`. |
| `Toast.Close` | `button` | Close button, labelled `Close`, with an X icon by default. |
| `Toast.Loader` | `div` | The loading spinner. |

`Toast.Root`, `Toast.Title`, and `Toast.Description` accept style props. The
button parts accept standard `button` props.

## Behaviour

- Up to four toasts are visible simultaneously by default. Additional toasts
  wait in a queue, and their auto-dismiss timers start only once they become
  visible.
- Auto-dismiss timers pause while the pointer hovers or focus is inside a
  toast, while the browser tab is hidden, or while a modal [Overlay](/overlay)
  is open, and resume with their remaining duration afterward.
- Standard toasts can be dismissed by swiping; loading toasts cannot be swiped
  away.
- Toasts do not trap focus, block page interaction, or close on `Escape`.

## Accessibility

Toasts render inside a landmark region labeled `"Notifications"`. Visual toast
content is not announced automatically; pass an `announce` string to broadcast
a message to screen readers via the polite live region shared with
[`announce()`](/announce).

```tsx
toast.success('Invite sent', { announce: 'Invite sent to Sam' })
```

If focus is inside a toast when it closes, focus returns to the previously
focused element.

### Keyboard interactions

| Key | Description |
| --- | --- |
| `Alt` + `T` | Moves focus to the front toast. Change it with `toaster.hotkey`. |
| `Tab` | Moves focus through the buttons in a toast. |
| `Space` / `Enter` | On an action, cancel or close button, runs it and dismisses the toast. |
