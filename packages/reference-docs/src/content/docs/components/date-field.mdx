# DateField

DateField formats and edits dates as locale-specific text while storing values
as ISO strings (`YYYY-MM-DD`). Pair it with `DateField.Picker` to add a popup
calendar.

<Preview>
  <DateFieldDemo />
</Preview>

```tsx
import { useState } from 'react'
import { Label } from '@reference-ui/react'
import { DateField, type ISODate } from '@reference-ui/lib'

export function StartDate() {
  const [date, setDate] = useState<ISODate | null>('2026-10-17')
  return (
    <>
      <Label htmlFor="start">Start date</Label>
      <DateField id="start" value={date} onChange={setDate} locale="en-GB">
        <DateField.Input />
        <DateField.Trigger aria-label="Open calendar" />
        <DateField.Picker />
      </DateField>
    </>
  )
}
```

## Import

```tsx
import { DateField } from '@reference-ui/lib'
```

## Anatomy

```tsx
<DateField>
  <DateField.Input />
  <DateField.Trigger />
  <DateField.Picker>
    <DateField.Calendar />
  </DateField.Picker>
</DateField>

<DateField.Range>
  <DateField.Start />
  <DateField.End />
  <DateField.Trigger />
  <DateField.Picker />
</DateField.Range>
```

Regardless of child order, DateField places the input first, the trigger after
it, and the picker below the field.

- Without children, DateField renders a standalone text input.
- When `DateField.Picker` is included without an explicit `DateField.Trigger`,
  DateField renders a default calendar-icon trigger button.
- When `DateField.Picker` has no children, it renders a default
  `DateField.Calendar` bound to the field.

## Examples

### Text only

Omit children to render a standalone text input without a calendar popover.

```tsx
<DateField id="due" value={date} onChange={setDate} locale="en-US" />
```

The display format follows the locale (`17/10/2026` in `en-GB`, `10/17/2026`
in `en-US`), and ISO input (`2026-10-17`) is also accepted. Years must be four
digits.

### Range

Use `DateField.Range` to pair start and end inputs with a shared range
calendar.

<Preview>
  <DateFieldRangeDemo />
</Preview>

```tsx
const [stay, setStay] = useState<DateRangeValue | null>(null)

<DateField.Range value={stay} onChange={setStay} locale="en-GB">
  <DateField.Start aria-label="Check-in" />
  <DateField.End aria-label="Check-out" />
  <DateField.Trigger aria-label="Open calendar" />
  <DateField.Picker />
</DateField.Range>
```

`onChange` fires when both dates are complete, valid, and in chronological
order, or with `null` when both inputs are cleared.

### Limits

`min`, `max`, and `isDateUnavailable` restrict which dates the field accepts.
Typed dates that violate these constraints are not passed to `onChange`.

In a single-date field, the default picker disables dates outside `min` and
`max`, while dates rejected by `isDateUnavailable` cannot be selected. To also
style unavailable dates in the calendar grid, pass `isDateUnavailable`
directly to `DateField.Calendar`:

```tsx
<DateField value={date} onChange={setDate} locale="en-GB" isDateUnavailable={isWeekend}>
  <DateField.Input />
  <DateField.Trigger aria-label="Open calendar" />
  <DateField.Picker>
    <DateField.Calendar isDateUnavailable={isWeekend} />
  </DateField.Picker>
</DateField>
```

### Forms

Pass `name` to submit the ISO value with a form. DateField adds a hidden
input; a disabled field submits nothing.

```tsx
<DateField name="start" value={date} onChange={setDate} locale="en-GB" />
```

For a range, a string `name` submits both dates under that name, and
`name={{ start: 'from', end: 'to' }}` submits them separately.

## API reference

### DateField

Without children, DateField renders an `input` element and accepts standard
`input` props. With children, it renders a wrapper `div` around the parts
while forwarding `id`, `placeholder`, and input event handlers to
`DateField.Input`.

<Reference name="DateFieldProps" headingLevel={4} />

DateField throws an error if a required prop is missing or if `min` and `max`
are invalid or out of order.

`onChange` fires as soon as the typed text forms a complete, valid date that
differs from `value`, or with `null` when the input is cleared. Incomplete
edits do not trigger `onChange`. On blur or Enter, invalid or incomplete text
reverts to the last committed `value` and marks the input invalid.

The input carries these data attributes:

| Data attribute | Present when |
| --- | --- |
| `[data-invalid]` | The last commit failed, or `value` is outside the limits. |
| `[data-editing]` | The text has been edited and not yet committed. |
| `[data-empty]` | The input is empty. |

### DateField.Range

The root container for a date range field. Renders a `div` and accepts
standard `div` props. Locale, constraint, state, and `form` props behave the
same as on DateField, while `value`, `onChange`, and `name` accept range
values.

<Reference name="DateFieldRangeProps" headingLevel={4} />

### Parts

| Part | Renders | Description |
| --- | --- | --- |
| `DateField.Input` | `input` | The text input of a single field. Takes input props. |
| `DateField.Start` | `input` | The start input of a range. Takes input props. |
| `DateField.End` | `input` | The end input of a range. Takes input props. |
| `DateField.Trigger` | `button` | Opens and closes the picker. Defaults to a calendar icon. |
| `DateField.Picker` | `div` | The popup container. Accepts [Overlay.Content](/overlay) props, with `placement` defaulting to `'bottom-start'`. |
| `DateField.Calendar` | [Calendar](/calendar) | A calendar bound to the field. Takes Calendar props, all optional. |

Input props managed by DateField (such as `value`, `role`, and ARIA
attributes) take precedence over props passed directly. Custom `onKeyDown`,
`onBlur`, and `onClick` handlers run before DateField's internal handlers;
call `event.preventDefault()` to suppress the default behavior.

## Accessibility

Associate a `Label` with the input via `htmlFor`, as shown in the first
example. For a range field, provide an `aria-label` on both `DateField.Start`
and `DateField.End`.

When a picker is present, the input has `role="combobox"` and clicking it
opens the calendar.

`DateField.Trigger` is excluded from the tab order (`tabIndex={-1}`) because
keyboard users open the picker from the input with `Alt+ArrowDown`. Always
provide an `aria-label` on the trigger for pointer and touch screen-reader
users.

### Keyboard interactions

| Key | Action |
| --- | --- |
| `Alt` + `ArrowDown` | Opens the picker. |
| `Escape` | Closes the picker. In a range field, also reverts uncommitted edits. |
| `Enter` | Commits the typed text. |
| `ArrowUp` / `ArrowDown` | Steps the day, month or year under the caret by one. |
| `Shift` + `ArrowUp` / `ArrowDown` | Steps it by ten. |

Arrow-key stepping requires a complete date in the input. Steps that would
exceed `min` or `max` are ignored.
