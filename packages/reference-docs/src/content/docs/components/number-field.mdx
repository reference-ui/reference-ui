# NumberField

NumberField is a locale-formatted number input with optional increment and
decrement stepper buttons.

<Preview>
  <NumberFieldDemo />
</Preview>

```tsx
import { useState } from 'react'
import { Label } from '@reference-ui/react'
import { NumberField } from '@reference-ui/lib'

export function Quantity() {
  const [quantity, setQuantity] = useState<number | null>(1)
  return (
    <>
      <Label htmlFor="quantity">Quantity</Label>
      <NumberField value={quantity} onChange={setQuantity} locale="en-GB" min={0} max={100}>
        <NumberField.Group>
          <NumberField.Decrement aria-label="Decrease quantity" />
          <NumberField.Input id="quantity" />
          <NumberField.Increment aria-label="Increase quantity" />
        </NumberField.Group>
      </NumberField>
    </>
  )
}
```

NumberField is always controlled. `value` is a number, or `null` when the
field is empty, and `locale` is required.

## Import

```tsx
import { NumberField } from '@reference-ui/lib'
```

## Anatomy

```tsx
<NumberField>
  <NumberField.Group>
    <NumberField.Decrement />
    <NumberField.Input />
    <NumberField.Increment />
  </NumberField.Group>
</NumberField>
```

- `NumberField` manages state and renders the root `div`.
- `NumberField.Group` renders the shared [Field](/field) border and focus
  ring. It must be the sole direct child of `NumberField`.
- `NumberField.Input` renders the text input. `NumberField.Group` requires
  exactly one `NumberField.Input` as a direct child.
- `NumberField.Decrement` and `NumberField.Increment` are optional stepper
  buttons (at most one of each) placed as direct children of
  `NumberField.Group`.

Additional elements, such as unit prefixes or suffixes, can be placed inside
`NumberField.Group` alongside the input and steppers. Invalid part nesting
throws a descriptive error.

Without children, `NumberField` renders the default layout above with stepper
buttons labelled "Decrement" and "Increment".

## Examples

### Formatting

`formatOptions` takes `Intl.NumberFormat` options. The display follows the
locale; the value stays a plain number. With `style: 'percent'`, `0.15`
shows as `15%` and `step` defaults to `0.01`.

<Preview>
  <NumberFieldFormatDemo />
</Preview>

```tsx
<NumberField
  value={price}
  onChange={setPrice}
  locale="en-GB"
  formatOptions={{ style: 'currency', currency: 'GBP' }}
>
  <NumberField.Group>
    <NumberField.Input id="price" />
  </NumberField.Group>
</NumberField>
```

Compact notation and `signDisplay: 'never'` cannot be parsed back from edited
text and will throw an error.

### Typing and committing

As the user types, `onChange` fires whenever the text parses to a new number,
before `min`, `max`, or `step` constraints are applied. Incomplete input such
as `-` does not fire `onChange`, and clearing the input calls
`onChange(null)`.

Blurring the input, pressing Enter, or activating a stepper commits the
current value. Unparseable text reverts to the last committed value and marks
the field invalid until the next edit.

### Snap to step

`commitBehavior` controls how values that fall outside `min`/`max` or between
steps are handled on commit:

| Value | On commit |
| --- | --- |
| `'none'` | Clamps to `min` and `max`. |
| `'snap'` | Rounds to the nearest step, then clamps. |
| `'validate'` | Keeps the value and marks the field invalid. |

```tsx
<NumberField value={value} onChange={setValue} locale="en-GB" min={0} max={100} step={5} commitBehavior="snap">
  <NumberField.Group>
    <NumberField.Input aria-label="Volume" />
  </NumberField.Group>
</NumberField>
```

### Validate

When `commitBehavior="validate"`, `onInvalidCommit` is called on each invalid
commit with the attempted number and the failure reason (`'out-of-range'` or
`'off-step'`). It runs after `onChange` and leaves the value unchanged.

```tsx
<NumberField
  value={value}
  onChange={setValue}
  onInvalidCommit={(attempted, reason) => setError(reason)}
  locale="en-GB"
  min={1}
  max={10}
  commitBehavior="validate"
>
  <NumberField.Group>
    <NumberField.Input aria-label="Seats" />
  </NumberField.Group>
</NumberField>
```

### Forms

Pass `name` to include the raw numeric value in form submissions via a hidden
input (or an empty string when `value` is `null`). Submitting the form commits
any in-progress edit first. Form submission is blocked if the input text
cannot be parsed, or if the value violates `step`, `min`, or `max` in `'snap'`
or `'validate'` mode. Setting the `invalid` prop alone does not block
submission.

```tsx
<NumberField name="quantity" value={quantity} onChange={setQuantity} locale="en-GB" required>
  <NumberField.Group>
    <NumberField.Input aria-label="Quantity" />
  </NumberField.Group>
</NumberField>
```

### Warning

Pass `status="warning"` to `NumberField.Group` to apply the warning border
style without marking the input invalid.

## API reference

### NumberField

Renders a `div` and takes `div` props and style props.

<Reference name="NumberFieldProps" headingLevel={4} />

### NumberField.Group

Renders a `div` with `role="group"` and takes `div` props and style props.

<Reference name="NumberFieldGroupProps" headingLevel={4} />

### NumberField.Input

Renders an `input type="text"` and takes `input` props. NumberField sets
`value`, `type`, `inputMode`, `name`, `min`, `max`, `step`, `disabled`,
`readOnly`, `required` and `aria-invalid`. `autoComplete` and `autoCorrect`
default to `'off'` and `spellCheck` to `false`.

### NumberField.Increment and NumberField.Decrement

Each renders a `button` and accepts standard `button` props. An accessible
name via `aria-label` or `aria-labelledby` is required; without one, the
button renders nothing. Passing children replaces the default plus or minus
icon.

Each stepper is automatically disabled when the value reaches its
corresponding `min` or `max` bound, or when the field is disabled or
read-only.

### Data attributes

| Attribute | On | Present when |
| --- | --- | --- |
| `[data-disabled]` | root, Group, Input, steppers | Disabled. A stepper also has it at its bound. |
| `[data-readonly]` | root, Group, Input | Read-only. |
| `[data-required]` | root, Group, Input | Required. |
| `[data-invalid]` | root, Group, Input | Invalid. |
| `[data-empty]` | root, Group, Input | The field is empty. |
| `[data-editing]` | root, Group, Input | Typed text is not yet committed. |
| `[data-focused]` | Group | The input has focus. |
| `[data-status]` | Group | `'warning'` when `status="warning"`. |
| `[data-pressed]` | steppers | The stepper is held down. |

## Accessibility

`NumberField.Input` renders a text input so screen readers announce the
locale-formatted string. Label it with `htmlFor`, a wrapping `label`,
`aria-label`, or `aria-labelledby`. The stepper buttons are excluded from the
tab order (`tabIndex={-1}`) since keyboard users adjust values with the arrow
keys.

Pressing and holding a stepper button repeats the step continuously. Touch
presses on stepper buttons do not move focus to the input, preventing the
mobile on-screen keyboard from opening.

### Keyboard interactions

| Key | Description |
| --- | --- |
| `ArrowUp` | Adds one step. |
| `ArrowDown` | Subtracts one step. |
| `Shift` + `ArrowUp` / `ArrowDown` | Steps by ten times `step`. Shift-clicking a stepper does the same. |
| `Home` | Sets the value to `min`, when `min` is set. |
| `End` | Sets the value to `max`, when `max` is set. |
| `Enter` | Commits typed text. With nothing typed, Enter submits the form as usual. |
