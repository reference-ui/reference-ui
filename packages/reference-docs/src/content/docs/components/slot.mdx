# Slot

Slot provides named layout regions for custom compound components. Each
subcomponent registers its element under a slot ID, and the parent layout
renders each slot in its designated position regardless of the order children
are passed.

<Preview>
  <SlotDemo />
</Preview>

```tsx
import type { ReactNode } from 'react'
import { Div, H3 } from '@reference-ui/react'
import { createSlotRootContext } from '@reference-ui/lib'

const CardSlots = createSlotRootContext()

function Card({ children }: { children: ReactNode }) {
  return (
    <CardSlots.Provider>
      {children}
      <CardLayout />
    </CardSlots.Provider>
  )
}

function CardTitle({ children }: { children: ReactNode }) {
  CardSlots.useSlotRegistration({ slotId: 'title', element: <H3>{children}</H3> })
  return null
}

function CardActions({ children }: { children: ReactNode }) {
  CardSlots.useSlotRegistration({ slotId: 'actions', element: <Div>{children}</Div> })
  return null
}

function CardLayout() {
  const title = CardSlots.useSlot('title')
  const actions = CardSlots.useSlot('actions')
  return (
    <Div>
      {title?.element}
      {actions?.element}
    </Div>
  )
}
```

Consumers can pass subcomponents in any order, while the layout controls where
each region is rendered:

```tsx
<Card>
  <CardActions>
    <Button>Publish</Button>
  </CardActions>
  <CardTitle>Publish this draft?</CardTitle>
</Card>
```

Slot renders no wrapper elements and does not reparent DOM nodes. To render
elements into a different DOM container, use [Portal](/portal).

## Import

```tsx
import { createSlotRootContext } from '@reference-ui/lib'
```

## Usage

1. Call `createSlotRootContext()` once per component, at module scope.
   Each call gets its own registry, so two components never share slots.
2. Wrap the component in its `Provider`, and render the layout after
   `children`.
3. In each part, call `useSlotRegistration` with a `slotId` and the
   element to show. Return `null`: the layout renders the element.
4. In the layout, read regions with `useSlot(id)` or `useSlots(filter)`.

Slot content updates in place: when a subcomponent re-renders with new
children, the layout updates without unmounting and remounting the element.

### Meta

Pass `meta` to attach data to a registration, and type it on the root:

```tsx
const ToolbarSlots = createSlotRootContext<{ align: 'start' | 'end' }>()

ToolbarSlots.useSlotRegistration({ slotId: 'item', element, meta: { align: 'end' } })

const endItems = ToolbarSlots.useSlots(slot => slot.meta?.align === 'end')
```

### Visibility

Pass a `visibility` object when registering a slot and resolve it in the layout
with `resolveSlotVisibility`, which returns `'visible'`, `'hidden'`, or
`'unmounted'`. Hiding a slot preserves its registration. Include any reactive
visibility flags in `deps` so the layout updates when they change.

```tsx
CardSlots.useSlotRegistration(
  { slotId: 'footer', element, visibility: { hidden: collapsed } },
  [collapsed],
)

const footer = CardSlots.useSlot('footer')
const state = resolveSlotVisibility(footer?.visibility)
```

## API reference

### createSlotRootContext

Creates an isolated slot registry and returns its provider and hooks:

<Reference name="SlotRootContext" headingLevel={4} />

All slot hooks throw an error if called outside their corresponding `Provider`.

### useSlotRegistration options

Options passed to `useSlotRegistration(options, deps)` when registering a slot
element.

<Reference name="UseSlotRegistrationOptions" headingLevel={4} />

`deps` defaults to `[]`. Changes to `slotId` or `deps` update the registration
in place; `element` updates automatically without being listed in `deps`.

### Helpers

| Export | Description |
| --- | --- |
| `resolveSlotVisibility(visibility?)` | Returns `'visible'`, `'hidden'`, or `'unmounted'`. `hidden` takes precedence over `unmounted`. |
| `transformSlotElements(slots, createProps)` | Clones each slot's element with props from `createProps(slot)`. |
| `createSlotCacheKey(slots)` | A string key built from the sorted slot ids. |
| `SlotRoot` | The registry class, for passing a custom `root` to `Provider`. |
