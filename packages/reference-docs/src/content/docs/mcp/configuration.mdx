# Configuration

Configure which components and icons the MCP server exposes in `ui.config.ts`,
and control its transport and project path with command-line flags or
environment variables.

## Config options

```ts {7-11}
// ui.config.ts
import { defineConfig } from '@reference-ui/core'

export default defineConfig({
  name: 'my-app',
  include: ['src/**/*.{ts,tsx}'],
  useReferenceIcons: false,
  mcp: {
    include: ['@acme/design-system'],
    exclude: ['@acme/design-system:LegacyButton'],
  },
})
```

| Option | Default | Description |
| --- | --- | --- |
| `useReferenceLibrary` | `true` | Show `@reference-ui/lib` components to your agent. |
| `useReferenceIcons` | `true` | Search `@reference-ui/icons` with `list_icons`. Turn it off when you use your own icons. |
| `mcp.include` | None | Packages and files to scan alongside your own source. |
| `mcp.exclude` | None | Components and files to leave out. |

Snake-case aliases (`use_reference_library` and `use_reference_icons`) are also
accepted.

The server reads these options when it builds its model. Restart the server
after changing them.

### Include and exclude

`mcp.include` and `mcp.exclude` take these entries:

| Entry | Example | Meaning |
| --- | --- | --- |
| A package | `@acme/design-system` | Every component the package exports. Include only. |
| A package component | `@acme/design-system:Button` | One component from a package. |
| A file glob | `legacy/**` | Files matched from the project root. |

Packages must be scoped (start with `@`). Without `mcp.include`, the server
scans only your own source files.

## Command-line options

| Option | Default | Description |
| --- | --- | --- |
| `[project]` | None | The project to serve, as a path. |
| `--project <path>` | None | Project directory to serve. Takes precedence over the positional `[project]` argument. |
| `--transport <stdio\|http>` | `stdio` | Transport protocol (`stdio` or `http`). |
| `--http` | None | Shorthand for `--transport http`. |
| `--host <host>` | `127.0.0.1` | The HTTP host. |
| `--port <port>` | `3697` | The HTTP port. |
| `-v, --version` | None | Print the version. |

Passing `--host` or `--port` without `--transport` starts the HTTP server.
Over HTTP the server answers `POST` requests at `/mcp`.

## Environment variables

| Variable | Description |
| --- | --- |
| `REF_PROJECT` | The project to serve, used when no path is passed. |
| `REF_REGISTRY_PATH` | Where the project registry lives. Defaults to `~/.reference-ui/registry.json`. |
| `REF_DEBUG` | Print debug logs to stderr. `DEBUG` works too. |

## Project resolution

Each MCP session operates on one active project. If you explicitly specify a
project via `--project` or `REF_PROJECT`, the server selects it even if it has
not been synced yet (returning a notice to run `ref sync`). Otherwise, the
server selects the first synced project it finds in this order:

1. The current working directory.
2. An ancestor directory containing `ui.config.ts`.
3. A workspace package containing `ui.config.ts` (discovered from
   `pnpm-workspace.yaml` or `package.json#workspaces`, ordered by path).
4. The most recently used project recorded in `~/.reference-ui/registry.json`.

Selecting a project with `select_project` records it in the registry for future
sessions. Agents can switch the active project with `select_project` or pass a
`project` path to an individual tool call (see [Tools](/mcp-tools)).
