# MCP

The Reference UI MCP server exposes your project's design system to AI coding
agents, including your components, their prop types, real call-site examples,
design tokens, and available icons.

## What your agent can ask

| Your agent asks | The server answers with |
| --- | --- |
| Which components does this project have? | Your components, the library components and the primitives your JSX uses. |
| What props does `Card` take? | Each prop's type, default and description. |
| How is `Card` used? | Call sites captured from your code. |
| Which colours can I use? | Your token paths and values. |
| Is there a trash icon? | Matching icons from `@reference-ui/icons`. |

Each question maps to one tool. See [Tools](/mcp-tools) for the full list.

## How it works

When loading a project, the server combines two sources into a unified model:

- The generated types and token definitions written to `.reference-ui/` by
  `ref sync` (see [Sync](/sync)).
- Static analysis of your source files using Atlas, Reference UI's component
  analyzer.

Atlas indexes exported components and records their JSX call sites across your
project files and any packages listed in
[`mcp.include`](/mcp-configuration#config-options), ignoring the rest of
`node_modules`. If a component's prop types cannot be statically resolved, Atlas
attaches a diagnostic warning rather than guessing.

## Unsynced projects

If a project has not been synced yet, the server falls back to built-in
primitives, `@reference-ui/lib` components, and the style props reference, and
includes a notice in each response prompting the agent to run `ref sync`.
