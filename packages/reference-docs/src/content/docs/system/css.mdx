# CSS

`css()` turns a style object into a class name you can put on any element.
`recipe()` turns a set of named variants into a function that returns the
class names for one choice of variants. Both are plain JavaScript calls; the
compiler reads them from your source and writes their rules into the
stylesheet ahead of time, so nothing is injected at runtime.

## `css()`

```tsx
import { css } from '@reference-ui/react'

const card = css({
  padding: '4r',
  bg: 'surface',
  color: 'text',
  borderRadius: 'card',
  _hover: { bg: 'surface/80' },
})

<article className={card}>…</article>
```

A style object takes the same keys and values as [style props](/style-props):
CSS properties in camelCase, their shorthands, token names, rhythm units,
conditions and breakpoints. Each property and value becomes one atomic class,
so two calls that share a declaration share its class.

### Combine styles

`css()` takes any number of style objects, or arrays of them. A later object
wins for the same property; `null`, `false` and `undefined` are skipped:

```ts
const button = css(
  { padding: '2r', color: 'text' },
  isActive && { color: 'brand' },
  size === 'lg' ? { padding: '4r' } : null,
)
```

A `null`, `false` or `undefined` value inside an object is skipped too, so
`{ color: undefined }` never overrides an earlier `color`.

### Signature

```ts
function css(...styles: Array<CssStyles | CssStyles[]>): string

type CssStyles = SystemStyleObject | undefined | null | false
```

Returns a space-separated class string, or `''` when every input is empty.

## Values

| Value | Example | Result |
| --- | --- | --- |
| Token name | `color: 'brand'` | `var(--colors-brand)` (see [Tokens](/tokens)) |
| Token reference | `border: '1px solid {colors.line}'` | references expand inside any string |
| Opacity or tone | `bg: 'brand/40'`, `bg: 'brand/soft'` | `color-mix(…)` |
| Rhythm | `gap: '3r'` | `calc(3 * var(--spacing-root))` (see [Spacing](/spacing)) |
| Number | `width: 42`, `opacity: 0.5` | `42px` on length properties, bare otherwise |
| Any CSS | `bg: 'linear-gradient(…)'` | printed as written |
| Important | `color: 'brand !important'` or `'brand!'` | marks the declaration `!important` |
| Custom property | `'--card-gap': '2r'` | the property keeps its casing |

## Conditions

Keys that start with `_` are named conditions such as `_hover`, `_focusVisible`
and `_dark`; [Style props](/style-props#conditions) lists them. Keys that start
with `&` are selectors relative to the element, and keys that start with `@`
are at-rules:

```ts
css({
  color: 'text',
  _hover: { color: 'brand' },
  '& > svg': { flexShrink: 0 },
  '&:not(:first-child)': { marginTop: '2r' },
  '@supports (backdrop-filter: blur(4px))': { backdropFilter: 'blur(4px)' },
})
```

Breakpoint keys (`md`, `lgDown`, `r`) are covered in
[Responsive](/responsive). Conditions nest, and a rule applies only when every
condition around it holds.

## What the compiler can read

The compiler finds style values by reading your source, without running it.
It reads:

- literal objects and values in a `css()` call, a `css` prop or a style prop;
- `const` objects and values, in the same file or imported from another;
- both branches of a ternary such as `active ? 'brand' : 'text'`;
- spreads of objects it can read, including `...(flag && extra)`.

A value it cannot read, such as the result of a function call or a string
built at runtime, gets no rule. `css()` still returns a class for it, but the
class paints nothing, and in development the browser console warns once,
naming the property, the value and the call site. `ref sync` also warns at the
call site.

When the choice is only known at runtime, write each option as its own
`css()` call and pick between the class names:

```ts
const toneClass = {
  info: css({ color: 'blue' }),
  danger: css({ color: 'red' }),
}

<p className={toneClass[kind]}>…</p>
```

### Pre-generate values with `staticCss`

For values that never appear in source, list them in `ui.config.ts`.
`staticCss` maps a property, optionally with a condition prefix, to the token
names to generate. `'*'` generates every token of the property's category:

```ts
// ui.config.ts
import { defineConfig } from '@reference-ui/neo'

export default defineConfig({
  name: 'my-app',
  include: ['src/**/*.{ts,tsx}'],
  staticCss: {
    color: ['*'],
    '_hover:bg': ['brand', 'surface'],
  },
})
```

A `staticCss` entry that names a token that does not exist fails `ref sync`.

## `recipe()`

A recipe is a component's closed set of looks. You describe the base styles,
the variant axes, and their defaults once; the recipe function returns the
classes for one selection:

```tsx
import { recipe } from '@reference-ui/react'

const button = recipe({
  className: 'button',
  base: { paddingInline: '4r', borderRadius: 'card' },
  variants: {
    tone: {
      primary: { bg: 'brand', color: 'white' },
      quiet: { bg: 'transparent', color: 'brand' },
    },
    size: {
      sm: { height: '8r' },
      lg: { height: '12r' },
    },
  },
  defaultVariants: { tone: 'primary', size: 'sm' },
  compoundVariants: [{ tone: 'quiet', size: 'lg', css: { fontWeight: '600' } }],
})

<button className={button({ tone: 'quiet' })}>Cancel</button>
```

| Option | Type | Description |
| --- | --- | --- |
| `className` | `string` | Names the recipe. Its classes are `<system name>__<className>…`; two recipes with the same name in one system fail sync. |
| `base` | style object | Styles every selection gets. |
| `variants` | `Record<axis, Record<value, style object>>` | One style object per value of each axis. Use `true` / `false` keys for a boolean axis. |
| `defaultVariants` | `Record<axis, value>` | The value used when a call omits an axis. |
| `compoundVariants` | `Array<{ [axis]: value, css: style object }>` | Styles that apply only when every listed axis matches. |

The returned function also has `raw(props)`, which returns the merged style
object instead of class names, plus `variantKeys`, `variantMap` and
`splitVariantProps(props)`. A variant value can be responsive:
`button({ size: { base: 'sm', md: 'lg' } })`.

Recipe rules live in the `recipes` layer, before `utilities`. A `css()` class
or style prop on the same element therefore always beats the recipe, whatever
the selector specificity.

Pass the recipe an object literal: the compiler reads the configuration from
source, and a recipe it cannot read fails sync.
