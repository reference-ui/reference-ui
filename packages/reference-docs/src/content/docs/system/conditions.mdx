# Conditions

Conditions apply styles under a specific state, attribute, colour mode, or
media query. Named conditions start with `_` and compile to the selectors or
at-rules listed on this page.

```tsx
<Button
  bg="brand"
  _hover={{ bg: 'brand/80' }}
  _focusVisible={{ outline: '2px solid {colors.brand}' }}
  _disabled={{ opacity: 0.5 }}
/>
```

## Use a condition

On a [primitive](/primitives), pass a condition as a prop with a style
object. The same condition keys work in [`css()`](/css), the `css`
prop, [recipes](/recipes), and [`globalCss()`](/global-css).

```tsx
import { css, recipe } from '@reference-ui/react'

const link = css({
  color: 'ink',
  _hover: { color: 'brand' },
  _visited: { color: 'ink/60' },
})

const button = recipe({
  className: 'button',
  base: { bg: 'brand', _active: { bg: 'brand/80' } },
  variants: {
    tone: {
      quiet: { bg: 'transparent', _hover: { bg: 'brand/10' } },
    },
  },
})
```

In `globalCss()`, the condition applies to the rule's selector:

```ts
import { globalCss } from '@reference-ui/system'

globalCss({
  '.field': {
    borderColor: 'line',
    _invalid: { borderColor: 'danger' },
  },
})
```

## Conditions on one value

To vary a single property across conditions, pass an object keyed by condition.
Use `base` for the default unconditional value:

```tsx
<Button color={{ base: 'ink', _hover: 'brand', _disabled: 'ink/40' }} />
```

Keys can be any named condition or breakpoint. Values are one level deep; to
combine multiple conditions, nest condition objects instead.

## Combine conditions

Conditions can be nested. A nested style applies only when all enclosing
conditions match:

```tsx
<Div
  bg="surface"
  _hover={{
    bg: 'surface/90',
    _dark: { bg: 'surface/70' },
  }}
/>
```

Breakpoint keys such as `md` nest the same way. See
[Responsive](/responsive).

```tsx
<Div p="2r" md={{ p: '4r', _hover: { p: '5r' } }} />
```

When a state condition is nested inside a pseudo-element condition, the state
applies to the element and the pseudo-element remains at the end of the
selector: `_before={{ _hover: { … } }}` compiles to
`&:is(:hover, [data-hover])::before`.

## Named conditions

In the tables below, `&` represents the element's generated class. Most state
conditions also match a corresponding `data-` or `aria-` attribute so headless
components and custom scripts can trigger them.

### Interaction

| Condition | Selector |
| --- | --- |
| `_hover` | `&:is(:hover, [data-hover])` |
| `_active` | `&:is(:active, [data-active])` |
| `_focus` | `&:is(:focus, [data-focus])` |
| `_focusVisible` | `&:is(:focus-visible, [data-focus-visible])` |
| `_focusWithin` | `&:is(:focus-within, [data-focus-within])` |
| `_visited` | `&:visited` |
| `_target` | `&:target` |
| `_dragging` | `&:is([data-dragging], [data-state="dragging"])` |
| `_grabbed` | `&:is([aria-grabbed=true], [data-grabbed])` |
| `_loading` | `&:is([data-loading], [aria-busy=true])` |

### Form state

| Condition | Selector |
| --- | --- |

| `_enabled` | `&:enabled` |
| `_checked` | `&:is(:checked, [data-checked], [aria-checked=true], [data-state="checked"])` |
| `_indeterminate` | `&:is(:indeterminate, [data-indeterminate], [aria-checked=mixed])` |
| `_required` | `&:required` |

### Disclosure and selection

| Condition | Selector |
| --- | --- |

### Structure

| Condition | Selector |
| --- | --- |
| `_first` | `&:first-child` |
| `_last` | `&:last-child` |
| `_only` | `&:only-child` |
| `_even` | `&:nth-of-type(even)` |
| `_odd` | `&:nth-of-type(odd)` |
| `_firstOfType` | `&:first-of-type` |
| `_lastOfType` | `&:last-of-type` |
| `_onlyOfType` | `&:only-of-type` |
| `_empty` | `&:empty` |

`_even` and `_odd` count siblings of the same element type.

### Pseudo-elements

| Condition | Selector |
| --- | --- |
| `_before` | `&::before` |
| `_after` | `&::after` |
| `_placeholder` | `&::placeholder, &[data-placeholder]` |
| `_selection` | `&::selection` |
| `_marker` | `&::marker` |
| `_file` | `&::file-selector-button` |
| `_backdrop` | `&::backdrop` |

`_before` and `_after` need a `content` value to render, such as
`content: '""'`.

### Group and peer

Group conditions style an element based on the state of an ancestor marked with
the `group` class or `data-group` attribute:

```tsx
<Div className="group" p="4r">
  <Span color="ink/60" _groupHover={{ color: 'brand' }}>
    Details
  </Span>
</Div>
```

Peer conditions style an element based on the state of a preceding sibling
marked with the `peer` class or `data-peer` attribute:

```tsx
<input className="peer" type="checkbox" />
<Span _peerChecked={{ fontWeight: '600' }}>Remember me</Span>
```

Each condition wraps the corresponding state selector from the tables above:

| State | Group | Peer |
| --- | --- | --- |
| hover | `_groupHover` | `_peerHover` |
| focus | `_groupFocus` | `_peerFocus` |
| focus-visible | `_groupFocusVisible` | `_peerFocusVisible` |
| active | `_groupActive` | `_peerActive` |
| checked | `_groupChecked` | `_peerChecked` |
| disabled | `_groupDisabled` | `_peerDisabled` |
| expanded | `_groupExpanded` | `_peerExpanded` |
| invalid | `_groupInvalid` | `_peerInvalid` |

For example, `_groupHover` and `_peerHover` compile to:

```css
&:is(:where(.group, [data-group]):is(:hover, [data-hover]) *)
&:is(:where(.peer, [data-peer]):is(:hover, [data-hover]) ~ *)
```

### Colour mode

| Condition | Selector or at-rule |
| --- | --- |
| `_light` | `[data-color-mode=light] &` |
| `_dark` | `[data-color-mode=dark] &` |
| `_osLight` | `@media (prefers-color-scheme: light)` |
| `_osDark` | `@media (prefers-color-scheme: dark)` |

`_light` and `_dark` match against an ancestor's `[data-color-mode]` attribute,
so they do not match on the element that sets `colorMode` itself. `_osLight`
and `_osDark` query the operating system preference via `prefers-color-scheme`.
See [Light and dark](/light-and-dark).

### Media

| Condition | At-rule |
| --- | --- |
| `_motionReduce` | `@media (prefers-reduced-motion: reduce)` |
| `_motionSafe` | `@media (prefers-reduced-motion: no-preference)` |
| `_print` | `@media print` |
| `_portrait` | `@media (orientation: portrait)` |
| `_landscape` | `@media (orientation: landscape)` |
| `_highContrast` | `@media (forced-colors: active)` |
| `_moreContrast` | `@media (prefers-contrast: more)` |
| `_lessContrast` | `@media (prefers-contrast: less)` |

`_fullscreen` is a selector, `&:fullscreen`.

### Direction

| Condition | Selector |
| --- | --- |
| `_ltr` | `[dir=ltr] &` |
| `_rtl` | `[dir=rtl] &` |

Both match an ancestor's `dir` attribute.

## Other selectors and at-rules

For selectors without a named condition, write the selector string as a key in
`css()`, the `css` prop, a recipe, or `globalCss()`. Use `&` to reference the
current element, either at the start of the selector or after an ancestor
selector:

```ts
css({
  '& > svg': { flexShrink: 0 },
  '&:not(:first-child)': { marginTop: '2r' },
  '&[data-orientation="vertical"]': { flexDirection: 'column' },
  '[data-sidebar="collapsed"] &': { display: 'none' },
})
```

Keys that start with `@media`, `@container` or `@supports` wrap the styles in
that at-rule:

```ts
css({
  '@media (hover: hover)': { _hover: { bg: 'surface/90' } },
  '@supports (backdrop-filter: blur(4px))': { backdropFilter: 'blur(4px)' },
})
```

An at-rule key without a query (such as a bare `@supports`) is ignored and
emits no CSS.

## Unknown conditions

An unknown `_` key (such as a typo like `_hovr`) is ignored and triggers a
warning during `ref sync`. The `StyleConditionKey` type includes all valid
named conditions. See [Types](/types).
