# Export a base system

A design system package exports its compiled base system under the
`./baseSystem` subpath so downstream projects can pass it to `extends` or
`layers`. See [Base systems](/base-systems) for what a base system contains.

## package.json

`ref sync` writes the base system to `.reference-ui/system/baseSystem.mjs`.
Point the `./baseSystem` export at it, and list it in `files` so it is
published:

```json
{
  "exports": {
    "./baseSystem": {
      "types": "./.reference-ui/system/baseSystem.d.mts",
      "import": "./.reference-ui/system/baseSystem.mjs"
    }
  },
  "files": [
    "dist",
    ".reference-ui/system/baseSystem.d.mts",
    ".reference-ui/system/baseSystem.mjs"
  ]
}
```

Do not publish a separate CSS stylesheet. Consuming applications compile a
single stylesheet that combines your `baseSystem` with their own styles.

## Build

Run `ref sync` before building your package. Downstream applications do not
re-scan your package source; they consume the precompiled styles and component
metadata from your `baseSystem` artifact. Add `ref sync` to your `prepack`
script so published builds are always up to date:

```json
{
  "scripts": {
    "prepack": "ref sync && npm run build"
  }
}
```

## Dependencies

Bundle `@reference-ui/react` into your package's build output and omit it from
`dependencies` and `peerDependencies`. Because `ref sync` generates
`@reference-ui/react` scoped to your system's `name`, bundling it ensures your
components render with the correct `data-layer` attribute in any consuming app.

Declare `react` as a peer dependency so the host application provides a single
React instance.

## Recipes

Your `recipe()` definitions stay in your package; consuming apps receive the
precompiled classes in your `baseSystem`.

## In a monorepo

A workspace package in the same monorepo does not need to be published first,
since sync resolves workspace imports directly. You can structure workspace
packages in two ways:

**Single system.** Run `ref sync` once at the repository root with `include`
globs covering both the app and the workspace package:

```ts
// ui.config.ts at the repository root
import { defineConfig } from '@reference-ui/core'

export default defineConfig({
  name: 'my-app',
  include: ['apps/web/src/**/*.{ts,tsx}', 'packages/ui/src/**/*.{ts,tsx}'],
})
```

**Separate systems.** Run `ref sync` in the workspace package, export its
`./baseSystem`, and reference it in the app's `extends` or `layers`. When a
workspace package has its own `.reference-ui/system/baseSystem.mjs`, sync
treats it as an external base system even if the app's `include` globs also
match its source directory.
