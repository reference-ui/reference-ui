# Tokens

Tokens name your design values, so every style can use the name instead of
the raw value.

## Define tokens

Call `tokens()` with a tree of categories. Each leaf has a `value`:

```ts
// src/theme/tokens.ts
import { tokens } from '@reference-ui/system'

tokens({
  colors: {
    brand: { value: '#4f46e5' },
    ink: { light: '#111111', dark: '#f5f5f5' },
  },
  radii: {
    card: { value: '0.5rem' },
  },
  spacing: {
    gutter: { value: '1.5rem' },
  },
})
```

Put the call in any file your `include` globs match. The next `ref sync`
collects it. Call `tokens()` in as many files as you like: sync merges them,
and a later definition of the same path wins.

## Use a token

Write the token's path without the category:

```tsx
import { Div, css } from '@reference-ui/react'

<Div color="ink" borderRadius="card" padding="gutter" />

const panel = css({ bg: 'brand' })
```

Nested groups join with a dot: `colors.brand.primary` is `brand.primary`. The
full path, `colors.brand.primary`, works too.

Each token becomes a CSS custom property named from its path in kebab case:
`colors.brand.primary` is `--colors-brand-primary`. Styles use the variable,
so changing a token's value never changes a class name.

A value that names no token is printed as written, so `color="#ff0000"` works
beside your tokens.

## Categories

The property decides which category a token name is looked up in. Each value
is a CSS string, printed into the token's variable as written.

| Category | Properties | Value |
| --- | --- | --- |
| `colors` | Every colour property: `color`, `background`, `borderColor`, `fill`, … | A colour: `'#4f46e5'`, `'oklch(60% 0.2 270)'` |
| `spacing` | `margin*`, `padding*`, `gap`, `rowGap`, `columnGap`, `inset`, `top`, `right`, `bottom`, `left` | A length: `'1rem'` |
| `sizes` | `width`, `height`, `minWidth`, `maxWidth`, `minHeight`, `maxHeight`, `size` | A length: `'40rem'` |
| `radii` | `borderRadius` and every corner radius | A length: `'0.5rem'` |
| `fonts` | `fontFamily` (see [Fonts](/fonts)) | A font stack: `'Inter, sans-serif'` |
| `fontSizes` | `fontSize` | A length: `'0.875rem'` |
| `fontWeights` | `fontWeight` | A weight: `'600'` |
| `lineHeights` | `lineHeight` | A number or length: `'1.5'` |
| `letterSpacings` | `letterSpacing` | A length: `'0.01em'` |
| `shadows` | `boxShadow` | A shadow: `'0 1px 2px rgb(0 0 0 / 0.1)'` |
| `zIndex` | `zIndex` | An integer: `'10'` |
| `gradients` | `backgroundImage` (on `background`, write the full path: `gradients.hero`) | A gradient: `'linear-gradient(to right, red, blue)'` |
| `easings` | `transitionTimingFunction` | A timing function: `'cubic-bezier(0.4, 0, 0.2, 1)'` |
| `durations` | `transitionDuration` | A time: `'200ms'` |
| `animations` | `animation`, `animationName` (see [Animation](/animation)) | An animation: `'spin 1s linear infinite'` |
| `tones` | The amount after a colour's slash (see [Tones](/tones)) | A percentage: `'10%'` |

Write numbers as strings: `zIndex: { modal: { value: '50' } }`. A number,
array or object value fails `ref sync` as an invalid token leaf.

Shorthands such as `p` and `bg` use the category of the property they stand
for.

## References

Inside any value, `{category.path}` refers to another token:

```ts
tokens({
  colors: {
    red: { 500: { value: '#ef4444' } },
    danger: { value: '{colors.red.500}' },
  },
  shadows: {
    focus: { value: '0 0 0 3px {colors.danger}' },
  },
})
```

A reference stays a variable in CSS: `--colors-danger` is
`var(--colors-red-500)`, so changing `red.500` changes `danger` too. One value
can hold several references. References work the same way in `css()`, style
props and `globalCss()`.

A reference to a token that does not exist fails `ref sync` and names the
reference. A whole value written without braces, such as `'red.500'`, is not a
reference: it prints as written and sync warns.

## Light and dark values

Give a token `light` and `dark` values. `value` fills the mode you don't name,
so beside `dark` it is the light value:

```ts
tokens({
  colors: {
    surface: { light: '#ffffff', dark: '#0b0b0f' },
    text: { value: '#111111', dark: '#f5f5f5' },
  },
})
```

Light values apply by default. Dark values apply inside an element with
`data-color-mode="dark"`. The `colorMode` prop on a primitive sets it. Put
it on your root primitive for the whole page, or on any primitive for one
part of it:

```tsx
<Div colorMode="dark" bg="surface" color="text">
  Dark, whatever the page uses.
</Div>
```

Modes nest: a `colorMode="light"` element inside a dark one is light again.
See [Primitives](/primitives#colour-mode).

## Opacity and tones

Add `/` and an amount to a colour token to make it translucent. A number sets
the amount directly, and a tone name uses a named amount from the `tones`
category:

```tsx
<Div bg="brand/40" borderColor="brand/soft" />
```

See [Tones](/tones) to define tones and choose between them.

## Private tokens

Tokens under a `_private` key work inside the system that defines them, but
a system that extends it never sees them:

```ts
tokens({
  colors: {
    _private: {
      focusGlow: { value: '#a5b4fc' },
    },
  },
})
```

Inside the defining system, write `_private.focusGlow`.

## Restrict values to tokens

By default a style prop accepts any CSS value as well as token names. The
`strict` option limits a category to its tokens:

```ts
// ui.config.ts
export default defineConfig({
  name: 'my-app',
  include: ['src/**/*.{ts,tsx}'],
  strict: ['colors', 'spacing'],
})
```

`strict` accepts `colors`, `radii` and `spacing`. In a strict category, a raw
value such as `color="#ff0000"` or a numeric opacity such as `brand/40` is a
type error. Strict colours still accept tones and the keywords `white`,
`black`, `inherit`, `currentColor` and `transparent`.

## Reference

```ts
function tokens(config: TokenConfig): void
```

| Leaf key | Type | Description |
| --- | --- | --- |
| `value` | `string` | The token's value. Fills the mode you don't name. |
| `light` | `string` | Light value. |
| `dark` | `string` | Dark value. |

A leaf needs `value`, `light` or `dark`. A leaf with one of them uses it in both
modes. Any other key starts a group, and a
key named `_private` starts a private group.
