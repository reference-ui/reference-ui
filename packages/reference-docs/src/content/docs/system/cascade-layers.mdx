# Cascade layers

Every generated rule is placed in a CSS
[`@layer`](https://developer.mozilla.org/en-US/docs/Web/CSS/@layer), so
precedence is determined by layer order rather than selector specificity or
source order.

## Layer order

Within a system, rules are organized into six layers, ordered from lowest to
highest precedence:

```css
@layer reset, global, base, tokens, recipes, utilities;
```

| Layer | Contents |
| --- | --- |
| `reset` | The CSS reset, when [`normalizeCss`](/config#normalizecss) is enabled. |
| `global` | `globalCss()` rules, `@keyframes`, and `@font-face`. |
| `base` | Reserved; unused by default. |
| `tokens` | Token custom properties, with their light and dark values. |
| `recipes` | `recipe()` classes. |
| `utilities` | Style props and `css()` classes. |

Because `utilities` comes after `recipes` and `global`, a style prop always
overrides a recipe or global rule on the same element without `!important`.

Empty layers are still declared in the `@layer` order, without a rule block.

## One layer per system

All six sublayers are nested inside a top-level layer named after your system's
[`name`](/config#name). Each upstream system in [`extends`](/config#extends)
and [`layers`](/config#layers) gets its own top-level layer ordered before
yours:

```css
@layer root { :root { --spacing-root: 0.25rem } }
@layer reference-icons, reference-ui, my-app;
@layer reference-icons {
  @layer reset, global, base, tokens, recipes, utilities;
  /* … */
}
@layer reference-ui {
  @layer reset, global, base, tokens, recipes, utilities;
  /* … */
}
@layer my-app {
  @layer reset, global, base, tokens, recipes, utilities;
  /* … */
}
```

Systems in `extends` come first, then systems in `layers`, then yours, each
group in config order. Each system's transitive dependencies are ordered before
it (for example, `reference-icons` before `reference-ui`). A system referenced
more than once is emitted once, at its first position.

Because outer layers take precedence before inner sublayers, your system's
rules always override upstream systems, even when your rule is in `global` and
the upstream rule is in `utilities`.

Only your system emits the CSS reset; upstream systems omit theirs, so your
`normalizeCss` setting controls the reset for the whole page.

Layer names are escaped as CSS identifiers. A system named `@acme/ui` is
escaped as `@layer \@acme\/ui`.

The `root` layer is ordered first and defines only the default
`--spacing-root` variable, so any custom `--spacing-root` value overrides it.
See [Spacing](/spacing#set-the-root).

## Your own CSS

In CSS, unlayered rules always take precedence over layered rules. Any
unlayered stylesheet imported alongside `@reference-ui/react/styles.css`
overrides Reference UI styles for the same property, regardless of selector
specificity or import order.

To give custom or third-party CSS lower precedence than Reference UI, wrap it
in a `@layer` declared before importing `@reference-ui/react/styles.css`:

```css
/* app.css, imported before @reference-ui/react/styles.css */
@layer legacy;

@layer legacy {
  .button { padding: 8px; }
}
```

Layer precedence is determined by the order in which layers are first
declared. If another library ships its own cascade layers, declaring its layer
name before importing `@reference-ui/react/styles.css` places it below
Reference UI.

For new global styles, prefer `globalCss()`, which places rules in your
system's `global` layer and supports token references.

## Browser support

The generated CSS requires browser support for:

- **Cascade layers** (`@layer`): every generated rule is placed in a layer.
- **Container queries** (`@container`): used by responsive breakpoints like `md` and the [`r` prop](/responsive#custom-widths).
- **`color-mix()`**: used by numeric opacity (`blue.500/40`) and [tones](/tones) (`blue.500/medium`).
