# Introduction

Reference UI is a styling system for React that compiles at build time. You
write three kinds of things: style props on primitives, tokens, and plain CSS
and JavaScript. `ref sync` hands them to a Rust engine, which turns them into
one stylesheet and the types that check your style values. The same engine
also powers Atlas, a map of your components. This section documents the authoring side, the part you
write.

## The authoring surface

Everything you write is ordinary TypeScript and TSX in files your
`ui.config.ts` `include` globs cover.

- **Style props and primitives.** A primitive is a typed React component for
  one HTML tag, such as `Div` or `Button`. Its style props are CSS properties
  written as JSX props: `<Div padding="4r" color="brand">`. See
  [Primitives](/primitives) and [Style props](/style-props).
- **Tokens.** `tokens()` names your design values (colours, spacing, radii and
  more) once. Every style value can then use the name instead of the raw
  value. See [Tokens](/tokens), [Spacing](/spacing), [Fonts](/fonts) and
  [Animation](/animation).
- **CSS and JS.** `css()` turns a style object into a class name for any
  element, `recipe()` builds a component's variants, and `globalCss()` writes
  rules for selectors you name yourself. See [CSS](/css),
  [Global CSS](/global-css) and [Responsive](/responsive).

The core ships no design of its own: no colours, no fonts, no spacing scale
beyond the rhythm unit. A project defines those values, or extends a system
that defines them, such as `@reference-ui/lib` (see
[Foundations](/foundations)).

## ref sync

`ref sync` reads `ui.config.ts`, runs each file that calls `tokens()`,
`font()`, `keyframes()` or `globalCss()` once in Node, and merges the results
into one description of your system. It also scans your source for every
`css()` call and every style prop. It passes both to the engine. Run it once
before a build, or in watch mode while you work; [Sync](/sync) covers the
command.

## The engine

The engine is written in Rust and never runs your files. It reads the system
description and the style values sync found, and compiles only those values.
A style value the engine never saw has no CSS rule, so `css()` and style props
work on values the engine can read from source. [CSS](/css) explains which
values count.

## The outputs

- **Stylesheet.** One `styles.css` with a rule per style value you used,
  ordered in cascade layers so later layers always win:
  `reset, global, base, tokens, recipes, utilities`.
- **Types.** TypeScript declarations for your tokens and style props, so an
  editor completes `color="…"` with your colour names.
- **Atlas.** An index of your project's components, their props, and how
  they are used across your JSX. The Reference MCP server runs Atlas to
  answer an AI assistant's questions about your components.
