# Tones and opacity

A tone is a named opacity token. Append `/<tone>` to any colour token, such as
`bg="blue.500/medium"`, to mix the colour with transparency using `color-mix()`.

## Define tones

Tones are defined in the `tones` token category as percentage strings. Each
tone can specify separate `surface` and `line` opacities:

```ts
// src/theme/tokens.ts
import { tokens } from '@reference-ui/system'

tokens({
  tones: {
    soft: { surface: { value: '8%' }, line: { value: '30%' } },
    hush: { value: '6%' },
  },
})
```

A tone with a single `value`, like `hush`, serves both roles. A tone with only
`surface` uses it for both roles too. A tone value can also reference another
tone, such as `'{tones.soft.surface}'`.

Tone values must be percentage strings such as `'10%'` or `'12.5%'`, since they
are interpolated into `color-mix()`.

The library ships four tones: `ghost`, `medium`, `firm` and `strong`.
See [Color](/color#tones) for their amounts.

## Apply a tone

Use `shade/tone` in any colour prop:

```tsx
import { Div } from '@reference-ui/react'

<Div bg="blue.500/soft" borderColor="blue.500/soft" />
```

The tone compiles to a CSS variable rather than a hardcoded percentage:

```css
background: color-mix(in srgb, var(--colors-blue-500) var(--tones-soft-surface), transparent);
border-color: color-mix(in srgb, var(--colors-blue-500) var(--tones-soft-line), transparent);
```

Updating a tone token updates every element that uses it without modifying your
colour tokens.

## Surface and line

The prop determines which amount a tone uses:

| Role | Props |
| --- | --- |
| `line` | `border*`, `outline*`, `color`, `caretColor`, `textDecoration`, `textDecorationColor`, `textEmphasisColor`, `columnRuleColor`, `stroke`, `boxShadow`, `textShadow` |
| `surface` | Every other colour prop, including `bg` and `fill` |

The `surface` opacity is used for backgrounds and fills, while the higher `line`
opacity keeps `1px` borders, outlines, and text legible.

## Numeric opacity

For a one-off amount, write a number after the slash:

```tsx
<Div bg="blue.500/40" />
```

This compiles to `color-mix(in srgb, var(--colors-blue-500) 40%, transparent)`.
Because the percentage is baked into the utility class, use named tones instead
when you want opacities that can be adjusted across your theme.

## Inside references

Tones can also be used inside `{...}` token references. The property where the
reference is used determines whether `surface` or `line` applies:

```ts
import { css } from '@reference-ui/react'

css({
  border: '1px solid {colors.blue.500/soft}',
  boxShadow: '0 0 0 3px {colors.blue.500/soft}',
})
```

Both use `line`, since `border` and `boxShadow` are line props.

## Light and dark

Because a tone mixes with transparency, it blends with the background in both
light and dark mode. To change the amount in dark mode, give the tone a `dark`
value:

```ts
tokens({
  tones: {
    soft: {
      surface: { value: '8%', dark: '12%' },
      line: { value: '30%' },
    },
  },
})
```

The colour token and the tone token resolve their dark values independently.
See [Light and dark](/light-and-dark).

## Strict colours

With `strict: ['colors']` in your config, colour props accept tones and reject
numeric opacity such as `blue.500/40`. `tones` is not a strict category. See
[Restrict values to tokens](/tokens#restrict-values-to-tokens).

## Unknown tones

An undeclared tone name logs a warning with the closest match and outputs the
value as written. Inside braces, an unknown tone is an error and its
declaration is dropped. See [Diagnostics](/diagnostics).
