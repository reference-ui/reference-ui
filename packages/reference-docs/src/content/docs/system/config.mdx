# Config

`ui.config.ts` configures your system name, source file globs, and upstream
base systems for `ref sync`.

```ts
// ui.config.ts
import { defineConfig } from '@reference-ui/core'
import { baseSystem } from '@reference-ui/lib/baseSystem'

export default defineConfig({
  name: 'my-app',
  include: ['src/**/*.{ts,tsx}'],
  extends: [baseSystem],
})
```

`ref init` generates a starter config. `defineConfig` is an identity helper
that provides TypeScript type checking.

Sync resolves `ui.config.ts`, `ui.config.js`, or `ui.config.mjs` (in that
order) in the target directory without searching parent directories. In watch
mode, changes to the config or its imported modules trigger a reload.

Keep config imports lightweight. Always import a package's base system from its
`baseSystem` subpath rather than the package root; if the config takes longer
than 750 ms to evaluate, sync logs a `BSS-W-SLOW-CONFIG` warning naming the
slow import.

## Required

### name

**Type**: `string`

Your system's identifier. Used as the top-level CSS `@layer` name and rendered
on primitives as the `data-layer` attribute. Must be a non-empty string without
double quotes, backslashes, or newlines.

### include

**Type**: `string[]`

Glob patterns specifying which source files to scan, resolved relative to the
config directory. Sync extracts style props, `css()`, and `recipe()` calls
from `.ts`, `.tsx`, `.js`, and `.jsx` files, and evaluates files that call
`tokens()`, `font()`, `keyframes()`, or `globalCss()`. Files outside `include`
are not compiled.

```ts
include: ['src/**/*.{ts,tsx}', 'content/**/*.mdx', '!src/**/*.test.tsx']
```

`.mdx` files are also scanned for token, font, and global CSS definitions.
Patterns prefixed with `!` exclude matching files. `node_modules`, `dist`,
`build`, `.git`, and `.reference-ui` are always excluded.

A pattern that matches no files logs a warning. Patterns support standard
globs (`*`, `**`, `?`, `[...]`, `{a,b}`) as well as parenthesized route groups
like `app/(marketing)/**`. Patterns that expand past 1,024 globs or nest braces
deeper than 64 levels fail sync; split them into shorter entries.

## Composing systems

`extends` and `layers` both take the `baseSystem` export of another synced
package. A system can appear in only one of them, and neither can list your
own `name`. See [Sharing](/sharing) for when to use
each.

### extends

**Type**: `BaseSystem[]`

**Default**: `[]`

Upstream systems to extend. Their tokens, fonts, keyframes, and compiled styles
are merged into your system, and their token names are included in your
generated types. Later entries override earlier ones, and your own definitions
override all extended systems.

### layers

**Type**: `BaseSystem[]`

**Default**: `[]`

Upstream systems whose components you render without merging their tokens into
your system. Their compiled CSS is included in your stylesheet and their
components retain their own token values, but their tokens are not added to
your generated types.

Each system in `extends` and `layers` receives its own CSS `@layer`, ordered
with `extends` systems first, then `layers` systems, then your own. See
[Cascade layers](/cascade-layers).

## Output

### strict

**Type**: `('colors' | 'radii' | 'spacing')[]`

**Default**: `[]`

Token categories that restrict style props to defined tokens only. Passing a
raw CSS value such as `color="#ff0000"` in a strict category produces a
TypeScript error. Strict `colors` still allow tone modifiers and the CSS
keywords `white`, `black`, `inherit`, `currentColor`, and `transparent`. See
[Tokens](/tokens#restrict-values-to-tokens).

### staticCss

**Type**: `Record<string, string[]>`

**Default**: `{}`

Style rules to pre-generate regardless of whether they appear in source files.
Each key is a style property (optionally prefixed with a condition), and each
value is an array of token names or `['*']` for all tokens in that property's
category.

```ts
staticCss: {
  color: ['*'],
  '_hover:bg': ['brand', 'surface'],
}
```

Sync fails if an entry names a token that does not exist. `'*'` on a property
with no token category logs a warning. See
[Dynamic styles](/dynamic-styles#a-token-name-chosen-at-runtime).

### normalizeCss

**Type**: `boolean`

**Default**: `true`

Includes the CSS reset in the compiled stylesheet. See
[Global CSS](/global-css#the-reset).

### jsxElements

**Type**: `string[]`

**Default**: `[]`

Additional component names to treat as style-prop hosts during extraction.
This is rarely needed because the compiler automatically traces components
that forward style props to a primitive. Applies only to components defined in
your project, not external packages. See
[Primitives](/primitives#your-own-components).

## Diagnostics

### logs

**Type**: `'compiler'[]`

**Default**: `[]`

Enables additional compiler diagnostics for expressions and spreads that cannot
be statically extracted. These diagnostics are included in the warning count
and listed under `ref sync --verbose`.

## MCP

These options are used by the Reference MCP server when indexing your project
and are ignored by `ref sync`. See [MCP configuration](/mcp-configuration).

### mcp

**Type**: `{ include?: string[]; exclude?: string[] }`

**Default**: none

Additional packages, components, or file globs for the MCP server to include
or exclude alongside your project source.

### useReferenceLibrary

**Type**: `boolean`

**Default**: `true`

Exposes `@reference-ui/lib` components in the MCP server
(`use_reference_library` is accepted as an alias).

### useReferenceIcons

**Type**: `boolean`

**Default**: `true`

Enables searching `@reference-ui/icons` via the `list_icons` MCP tool
(`use_reference_icons` is accepted as an alias).
