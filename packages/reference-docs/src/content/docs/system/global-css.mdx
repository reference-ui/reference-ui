# Global CSS

`globalCss()` defines global stylesheet rules for arbitrary CSS selectors such
as `body`, `:root`, or custom classes.

```ts
// src/theme/global.ts
import { globalCss } from '@reference-ui/system'

globalCss({
  ':root': {
    '--spacing-root': '0.3rem',
  },
  body: {
    fontFamily: 'body',
    color: 'text',
    backgroundColor: 'surface',
  },
  'a:focus-visible': {
    outline: '2px solid {colors.brand}',
    outlineOffset: '2px',
  },
})
```

Each top-level key is a standard CSS selector. Comma-separated selectors,
`:has()`, `:is()`, and vendor pseudo-elements such as `::-webkit-scrollbar` are
passed through as written. You can call `globalCss()` across multiple files
matched by your `include` globs.

## Values

Values resolve the same way as in [`css()`](/css#values): token names,
`{colors.brand}` references, rhythm units such as `4r`, and raw CSS values.
Properties set to `undefined` are omitted, and unknown property names are
ignored with a warning.

Custom property declarations are emitted as written unless the value is a token
reference like `'{colors.brand}'`, which resolves to `var(--colors-brand)`.
Setting `--spacing-root` on `:root` scales all rhythm units across the page (see
[Spacing](/spacing)).

## Nesting and conditions

Inside a rule, `&` refers to the parent selector. Named conditions such as
`_hover` work the same way as on [style props](/style-props#conditions):

```ts
globalCss({
  '.field': {
    borderColor: 'line',
    '& > [data-slot="icon"]': { color: 'muted' },
    _hover: { borderColor: 'brand' },
    _disabled: { opacity: 0.5 },
    _placeholder: { color: 'muted' },
  },
})
```

## Media and container queries

`@media` and `@container` keys wrap the rule:

```ts
globalCss({
  '.sidebar': {
    display: 'none',
    '@media (min-width: 900px)': { display: 'block' },
  },
})
```

An at-rule key at the top level wraps every selector inside it:

```ts
globalCss({
  '@media print': {
    nav: { display: 'none' },
    body: { color: 'black' },
  },
})
```

## Breakpoints

Breakpoint keys, range keys such as `mdDown` or `smToLg`, and responsive
objects and arrays work as they do on style props. In global CSS they compile
to viewport `@media` queries, whereas style props and `css()` compile to
`@container` queries. See [Responsive](/responsive).

```ts
globalCss({
  body: {
    fontSize: { base: '14px', lg: '16px' },
    padding: ['2r', null, '4r'],
    mdDown: { lineHeight: 1.4 },
  },
})
```

The `lg` value compiles to `font-size: 16px` inside `@media (min-width: 1024px)`.

## Where global rules sit

Global rules are placed in the `global` cascade layer, which has lower
precedence than recipes and utility classes. Style props and `css()` classes on
an element override global rules without needing `!important`. See
[Cascade layers](/cascade-layers).

## The reset

By default (`normalizeCss: true`), the stylesheet includes a minimal CSS reset
in the `reset` layer. It covers box sizing, default margins, media, form fonts
and reduced motion.

The reset does not make the page a container, so responsive styles need a
container type on `body`. `@reference-ui/lib` sets it. Without the lib, set it
yourself with `globalCss()`. See [Responsive](/responsive#mark-a-container).

To disable the reset, set `normalizeCss: false` in `ui.config.ts`:

```ts
// ui.config.ts
export default defineConfig({
  name: 'my-app',
  include: ['src/**/*.{ts,tsx}'],
  normalizeCss: false,
})
```

## Reference

```ts
function globalCss(rules: GlobalCssConfig): void
```

`GlobalCssConfig` maps selectors or top-level at-rules to style objects. Each
rule accepts camelCase CSS properties, custom properties (`--name`), nested `&`
selectors, named conditions, breakpoint and range keys, responsive values, and
`@media` or `@container` rules.
