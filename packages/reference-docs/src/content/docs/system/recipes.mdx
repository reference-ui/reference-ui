# Recipes

A recipe defines the variants of a component: base styles plus named
variants, such as `tone` and `size`. `recipe()` returns a function that gives
the class names for the variants you pick.

## Define a recipe

```tsx
import { recipe } from '@reference-ui/react'

const button = recipe({
  className: 'button',
  base: { paddingInline: '4r', borderRadius: 'card' },
  variants: {
    tone: {
      primary: { bg: 'brand', color: 'white' },
      quiet: { bg: 'transparent', color: 'brand' },
    },
    size: {
      sm: { height: '8r' },
      lg: { height: '12r' },
    },
  },
  defaultVariants: { tone: 'primary', size: 'sm' },
})

<button className={button({ tone: 'quiet' })}>Cancel</button>
```

Pass `recipe()` an inline object literal with a string `className`. A
recipe the compiler cannot read fails sync.

## Options

| Option | Type | Description |
| --- | --- | --- |
| `className` | `string` | Required. Names the recipe. Two recipes with the same name in one system fail sync. |
| `base` | style object | Styles every choice gets. |
| `variants` | `Record<string, Record<string, StyleObject>>` | One style object per value of each variant. Use `true` and `false` keys for a boolean variant. |
| `defaultVariants` | `Record<string, string>` | The value used when a call leaves a variant out. |
| `compoundVariants` | `Array<{ [variant]: value, css: StyleObject }>` | Styles that apply only when every listed variant matches. |

## Compound variants

A compound variant applies only when every variant it lists matches.
Here `quiet` buttons get a heavier font, but only at size `lg`:

```tsx
const button = recipe({
  // …
  compoundVariants: [{ tone: 'quiet', size: 'lg', css: { fontWeight: '600' } }],
})

button({ tone: 'quiet', size: 'lg' }) // gets fontWeight 600
button({ tone: 'quiet', size: 'sm' }) // does not
```

A key can match more than one value. Write it as an array:

```tsx
compoundVariants: [{ tone: 'quiet', size: ['sm', 'lg'], css: { fontWeight: '600' } }]
```

## Responsive variants

A variant value can be an object of [breakpoints](/responsive):

```tsx
<button className={button({ size: { base: 'sm', md: 'lg' } })}>Save</button>
```

The button is `sm` until its container reaches `md`, then `lg`. If the object
has no `base`, the default variant applies below the breakpoints it names.

Compound variants match the `base` value only. In the example above, a
compound for `size: 'lg'` does not apply at `md`.

## Values picked at runtime

Every value of every variant gets a class, so a value chosen at runtime
needs no `staticCss`:

```tsx
function SaveButton({ size }: { size: 'sm' | 'lg' }) {
  return <button className={button({ size })}>Save</button>
}
```

Responsive values work the same way. If any call passes a variable, sync
emits every breakpoint of that recipe.

## Helpers

The returned function also has:

- `raw(props)`, which returns the merged style object instead of class names;
- `variantKeys` and `variantMap`, which list the variants and their values;
- `splitVariantProps(props)`, which splits variant props from the rest.

Use `splitVariantProps` in a wrapper component. It returns
`[variants, rest]`: `rest` holds every other prop with its type intact, so
`onClick` and `children` pass through and never reach the recipe:

```tsx
import type { RecipeVariantProps } from '@reference-ui/react'
import type { ComponentProps } from 'react'

type ButtonProps = RecipeVariantProps<typeof button> & ComponentProps<'button'>

function Button(props: ButtonProps) {
  const [variants, { className, ...rest }] = button.splitVariantProps(props)
  return <button {...rest} className={`${button(variants)} ${className ?? ''}`} />
}
```

## Types

`RecipeVariantProps` gives the props type of a recipe:

```ts
import type { RecipeVariantProps } from '@reference-ui/react'

type ButtonVariants = RecipeVariantProps<typeof button>
// { tone?: 'primary' | 'quiet'; size?: 'sm' | 'lg' }
```

Each value also takes the [breakpoint](#responsive-variants) object form,
and a variant with `true` or `false` keys takes a boolean.

## Cascade layer

Recipe classes live in the `recipes` [cascade layer](/cascade-layers),
below utilities. A style prop or `css()` class on the same element always
wins over the recipe.
