# Base systems

A base system packages a system's tokens, fonts, keyframes, compiled styles,
and component metadata for downstream projects. `ref sync` writes it as the
`baseSystem` export of `.reference-ui/system/baseSystem.mjs`. Consuming
projects pass it to `extends` or `layers`, or to `extendSystem()` to override
its token values.

To publish one, see [Export a base system](/export-base-system). To
brand a shared system, see [Customization](/customization).

## baseSystem

Import a package's base system from its `baseSystem` subpath:

```ts
// ui.config.ts
import { defineConfig } from '@reference-ui/core'
import { baseSystem } from 'my-design-system/baseSystem'

export default defineConfig({
  name: 'my-app',
  include: ['src/**/*.{ts,tsx}'],
  extends: [baseSystem],
})
```

Your own base system is also exported from `@reference-ui/system`.

## What travels

| | `extends` | `layers` |
| --- | --- | --- |
| Tokens, fonts, and keyframes, usable by name in your styles and types | yes | no |
| Generated CSS: token variables, `@font-face`, and `@keyframes` rules | yes | yes |
| Global CSS, recipe classes, and style prop classes compiled by the system | yes | yes |
| `recipe()` definitions | no | no |
| Its `jsxElements` names, merged with yours | yes | no |
| Component prop schemas for style tracing | yes | yes |
| Your token overrides apply to its components | yes | no |

Recipes are precompiled by the upstream package: your sync receives their
compiled CSS classes, not their `recipe()` configurations. Tokens marked
`_private` still apply inside the upstream system's components, but are
excluded from your generated token types.

When a system is listed in `layers`, referencing its tokens in your own styles
logs a warning.

## Order

Each system is placed in its own [cascade layer](/cascade-layers), ordered
with `extends` systems first (in config order), then `layers` systems, then
your own.

Under `extends`, token definitions merge by leaf path:

- Later entries in `extends` override earlier ones.
- Your own tokens override all extended systems (sync logs a warning when your
  token replaces a different upstream value).
- Transitive `extends` chains are included automatically and deduplicated.

## Styling its components

Whether a package is in `extends` or `layers`, your app can pass style props
and its own tokens to the package's components. Component-specific props (such
as `tone`) are passed through to the component unchanged.

If style props on an external component don't apply, check that its package's
`baseSystem` is listed in `extends` or `layers`. See
[Diagnostics](/diagnostics#components-and-files).

## Config errors

If `extends` or `layers` is invalid, `ref sync` fails while loading the config
with `Config field 'extends' is invalid.` or
`Config field 'layers' is invalid.`:

| Cause | Fix |
| --- | --- |
| The field is not an array, or an entry is not an object or has no `name` | Pass a package's `baseSystem` export. |
| An entry has no synced data | Run `ref sync` in that package first. |
| A `layers` entry has no compiled styles | Run `ref sync` in that package, or list it under `extends`. |
| An entry matches your own `name`, or introduces a cycle through `extends` or `layers` | Remove the self-reference or cycle. |
| The same system appears more than once in a field | List each system once. |
| The same system appears in both `extends` and `layers` | Remove it from `layers`. |
| A system `name` contains a double quote, backslash, or newline | Rename the system. |

Importing a `baseSystem` from a package that has not run `ref sync` also fails
at load time.

## extendSystem()

`extendSystem()` returns a copy of a base system with overridden token values.
Pass the returned system to `extends` or `layers` in place of the original.

```ts
// ui.config.ts
import { defineConfig, extendSystem } from '@reference-ui/core'
import { baseSystem } from 'my-design-system/baseSystem'

const branded = extendSystem(baseSystem, {
  tokens: {
    colors: {
      brand: { light: '#0f766e', dark: '#5eead4' },
    },
  },
})

export default defineConfig({
  name: 'my-app',
  include: ['src/**/*.{ts,tsx}'],
  extends: [branded],
})
```

```ts
function extendSystem(
  base: BaseSystem,
  overrides: { tokens: TokenConfig }
): BaseSystem
```

| Parameter | Type | Description |
| --- | --- | --- |
| `base` | `BaseSystem` | A published base system, or the result of an earlier `extendSystem()` call. |
| `overrides.tokens` | `TokenConfig` | A token tree shaped like the `tokens()` input. Every leaf must be a token the base declares. |

The returned system preserves the base system's name, components, and compiled
styles, overriding only its token values in light and dark mode.

Pass only the extended copy to your config; do not list both the original base
system and its extended copy.

### Token values

Each token leaf accepts `value`, `light`, or `dark` as a string (numeric
values must be quoted).

| You write | Light | Dark |
| --- | --- | --- |
| `{ value: 'a' }` | `a` | `a` |
| `{ light: 'a' }` or `{ dark: 'a' }` | `a` | `a` |
| `{ light: 'a', dark: 'b' }` | `a` | `b` |
| `{ value: 'a', dark: 'b' }` | `a` | `b` |
| `{ value: 'a', light: 'b' }` | `b` | `a` |

Providing a single value (`value`, `light`, or `dark`) overrides both the
light and dark values from the base system.

A value can reference another token declared in the base system (such as
`{colors.brand}`) and use [rhythm units](/spacing): `2r` compiles to
`calc(2 * var(--spacing-root))`. `spacing.root` requires a plain CSS length,
since it defines `r`.

### Chained calls

You can pass an already-extended system to `extendSystem()` to apply
additional overrides:

```ts
const branded = extendSystem(baseSystem, {
  tokens: { colors: { brand: { value: '#0f766e' } } },
})

const final = extendSystem(branded, {
  tokens: { colors: { accent: { value: '#f59e0b' } } },
})
```

Overrides merge by leaf path, with later calls taking precedence.

### Errors

Invalid arguments throw an `ExtendSystemError` when the config loads:

| Message | Cause |
| --- | --- |
| `the first argument must be a published base system` | `base` is not a base system. |
| ``overrides need a `tokens` object`` | `overrides.tokens` is missing or not an object. |
| `unknown token <path> in <base>` | The base does not declare that token. |
| `token <path> needs a value, a light value or a dark value` | The token leaf has no `value`, `light`, or `dark` property. |
| `token <path> must be a string` | A token value is not a string. |
| `token <path> references itself` | A value references its own token. |
| `token <path> refers to unknown token` | A `{path}` reference names a token the base does not declare. |
| `token <path> has a brace that is not a {token.path} reference` | A value has a stray or empty brace. |
| `token <path> defines the rhythm root in rhythm units` | `spacing.root` uses `r`. |

Each message begins with `extendSystem:`.
