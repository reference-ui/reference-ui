# Element styles

Lib gives every [primitive](/primitives) a base look. Each primitive carries a
class named after its tag, such as `ref-table` or `ref-input`, and lib styles
those classes with `globalCss()`. The rules apply wherever your config extends
lib's `baseSystem`.

One rule targets the tag itself: `code` styles every `<code>` element on the
page, not only the `Code` primitive.

Colours come from lib's `ui.*` tokens, one group per element. See
[Color](/color).

## Page

| Selector | Look |
| --- | --- |
| `:root` | Sets `--spacing-root` to `0.25rem`, the size of `1r`. See [Spacing](/spacing). |
| `body` | `sans` at `4r` (16px), letter spacing `-0.01em`, `container-type: inline-size`. |

## Forms

Controls share one height, `8.5r` (34px). See [Sizes](/sizes).

| Element | Look | Tokens |
| --- | --- | --- |
| `Button` | `8.5r` tall, `3.5r` padding, `md` radius, weight 500. Three variants (below). | `ui.button.*` |
| `Input` (text types), `Select`, `Textarea` | Full width, `8.5r` tall, 1px border, `sm` radius. Textarea resizes vertically. | `ui.field.background`, `ui.field.border`, `ui.field.borderHover`, `ui.field.placeholder` |
| `Input type="checkbox"` | `4r` box with a tick when checked. | `ui.checkbox.*` |
| `Input type="radio"` | `4r` disc with a ring when checked. | `ui.radio.*` |
| `Input type="range"` | `1.5r` track, filled bar and a rounded thumb. | `ui.progress.bar.foreground` |
| `Input type="file"` | Field border, with a button-style picker. | `ui.field.*`, `ui.button.default.*` |
| `Progress`, `Meter` | Full width, `1.5r` rounded bar. `Meter` colours its optimum, suboptimum and low ranges. | `ui.progress.*`, `ui.meter.*` |
| `Fieldset` | Grid with `3r` gap, 1px border, `md` radius. | `ui.fieldset.border` |
| `Legend`, `Label` | `3.5r` (14px), weight 500. A checkbox inside a `Label` sits beside the text. | `ui.label.controlAccent` |

Pick a button variant with the `variant` prop:

| `variant` | Look |
| --- | --- |
| `default` (or none) | Grey fill, base text colour. |
| `primary` | Near-black fill in light mode, near-white in dark mode. |
| `ghost` | Transparent until hovered. |

Disabled controls take a not-allowed cursor. A disabled `Button` uses
`ui.button.disabled.*`; a disabled field drops to half opacity.

## Focus

A primitive focused from the keyboard shows a 2px outline in
`ui.focus.ring`, offset by 2px. A click on a button or link shows no ring.

Text inputs, selects and textareas take the `ui.focus.ring` border colour on
any focus, and add the outline only on keyboard focus. Browsers match
`:focus-visible` on a clicked text input, so lib tracks the input method
itself and sets `data-focus-visible` on the focused element when focus came
from the keyboard.

Importing anything from `@reference-ui/lib` starts that tracking. When your
app uses lib's styles without importing from it, start it yourself once:

```ts
import { setupFocusVisible } from '@reference-ui/lib'

setupFocusVisible()
```

`setupFocusVisible(doc?)` listens on `document`, or on the `Document` you pass.
Later calls do nothing, and it does nothing on the server.

To style keyboard focus yourself, target the attribute:

```ts
import { globalCss } from '@reference-ui/system'

globalCss({
  '.ref-input[data-focus-visible]': {
    outlineColor: 'blue.500',
  },
})
```

## Selection

Selected text inside a primitive uses `ui.selection.background` and
`ui.selection.foreground`: a near-black highlight in light mode and a
near-white one in dark mode.

## Override an element style

Target the element's class with your own `globalCss()`:

```ts
// src/theme/global.ts
import { globalCss } from '@reference-ui/system'

globalCss({
  '.ref-hr': {
    borderTopStyle: 'dashed',
  },
  '.ref-th': {
    textTransform: 'uppercase',
  },
})
```

Your global CSS sits in a later [cascade layer](/cascade-layers) than lib's,
so it wins. A style prop on one element still overrides both.

To change a colour everywhere lib uses it, change its `ui.*` token with
`extendSystem()`. See [Customization](/customization).
