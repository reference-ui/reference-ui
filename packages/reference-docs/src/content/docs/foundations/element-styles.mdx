# Element styles

`@reference-ui/lib` provides default styles for every [primitive](/primitives).
Each primitive renders a class named after its tag (such as `ref-table` or
`ref-input`) styled via `globalCss()`. These rules apply whenever your config
extends `@reference-ui/lib/baseSystem`.

One rule targets a bare HTML tag directly: `code` styles all `<code>` elements
on the page, not only the `Code` primitive.

Default colors reference the `ui.*` semantic token groups (see [Color](/color)).

## Page

| Selector | Default styles |
| --- | --- |
| `:root` | Sets `--spacing-root` to `0.25rem`, the size of `1r`. See [Spacing](/spacing). |
| `body` | `sans` at `4r` (16px), letter spacing `-0.01em`, `container-type: inline-size`. |

## Forms

Controls share one height, `8.5r` (34px). See [Sizes](/sizes).

| Element | Default styles | Tokens |
| --- | --- | --- |
| `Button` | `8.5r` tall, `3.5r` padding, `md` radius, weight 500. Three variants (below). | `ui.button.*` |
| `Input` (text types), `Select`, `Textarea` | Full width, `8.5r` tall, 1px border, `sm` radius. Textarea resizes vertically. | `ui.field.background`, `ui.field.border`, `ui.field.borderHover`, `ui.field.placeholder` |
| `Input type="checkbox"` | `4r` square checkbox with a checkmark indicator when checked. | `ui.checkbox.*` |
| `Input type="radio"` | `4r` circular radio control with an inner ring when checked. | `ui.radio.*` |
| `Input type="range"` | `1.5r` track, filled bar and a rounded thumb. | `ui.progress.bar.foreground` |
| `Input type="file"` | Field border, with a button-style picker. | `ui.field.*`, `ui.button.default.*` |
| `Progress`, `Meter` | Full width, `1.5r` rounded bar. `Meter` colours its optimum, suboptimum and low ranges. | `ui.progress.*`, `ui.meter.*` |
| `Fieldset` | Grid with `3r` gap, 1px border, `md` radius. | `ui.fieldset.border` |
| `Legend`, `Label` | `3.5r` (14px), weight 500. A checkbox inside a `Label` sits beside the text. | `ui.label.controlAccent` |

Pick a button variant with the `variant` prop:

| `variant` | Default styles |
| --- | --- |
| `default` (or none) | Grey fill, base text colour. |
| `primary` | Near-black fill in light mode, near-white in dark mode. |
| `ghost` | Transparent until hovered. |

Disabled controls use `cursor: not-allowed`. A disabled `Button` uses
`ui.button.disabled.*` tokens, while disabled fields use `0.5` opacity.

## Focus

Primitives focused via the keyboard display a `2px` outline in `ui.focus.ring`
with a `2px` offset. Pointer clicks on buttons and links do not trigger the
focus ring.

Text inputs, selects, and textareas change their border color to `ui.focus.ring`
on any focus, and add the outer focus ring only on keyboard focus. Because
browsers match native `:focus-visible` when clicking into a text input,
`@reference-ui/lib` tracks the active input modality and sets
`data-focus-visible` on elements focused via the keyboard.

Importing any module from `@reference-ui/lib` initializes this listener
automatically. If your app extends `@reference-ui/lib/baseSystem` without
importing runtime components from `@reference-ui/lib`, call
`setupFocusVisible()` once at startup:

```ts
import { setupFocusVisible } from '@reference-ui/lib'

setupFocusVisible()
```

`setupFocusVisible(doc?)` attaches listeners to `document` (or a custom
`Document` instance). Subsequent calls on the same document are no-ops, and it
is safe to call during SSR.

To style keyboard focus yourself, target the attribute:

```ts
import { globalCss } from '@reference-ui/system'

globalCss({
  '.ref-input[data-focus-visible]': {
    outlineColor: 'blue.500',
  },
})
```

## Selection

Selected text inside a primitive uses `ui.selection.background` and
`ui.selection.foreground`: a near-black highlight in light mode and a
near-white one in dark mode.

## Override an element style

Target the element's class with your own `globalCss()`:

```ts
// src/theme/global.ts
import { globalCss } from '@reference-ui/system'

globalCss({
  '.ref-hr': {
    borderTopStyle: 'dashed',
  },
  '.ref-th': {
    textTransform: 'uppercase',
  },
})
```

Your application's global CSS is placed in a later [cascade layer](/cascade-layers)
than the library's, so your rules take precedence. Style props on an individual
element still override both.

To customize a color across all primitives, override its `ui.*` token with
`tokens()` or `extendSystem()`. See [Customization](/customization).
