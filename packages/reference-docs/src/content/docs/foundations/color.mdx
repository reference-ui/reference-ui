# Color

A colour in use is a shade at a strength. The [palette](#palette) gives you the
shades. This page covers strength, the role a colour plays, and how colours
combine.

## Shades and tones

A **shade** is one fixed step of a ramp, such as `blue.500`. A **tone** is a
colour at a named strength, written `color/tone`: `blue.500/medium` is blue at
the medium strength. Reference UI ships four tones, `ghost`, `medium`, `firm`
and `strong`. Each holds two amounts, a surface and a line.

<ShadesAndTones />

```tsx
import { Div } from '@reference-ui/react'

// A shade: the solid step.
<Div bg="blue.500" />

// A tone: the same colour at the medium strength.
<Div bg="blue.500/medium" />
```

### Why tones matter

- **One colour, every strength.** A tone gives a range of tints from one ramp
  step, so you do not need a palette step for each lightness.
- **They take on what is behind them.** A tone mixes its colour with
  transparency, so `blue.500/medium` is a pale wash on a light page and a dim
  glow on a dark one, with no per-mode value.
- **They are retuned in one place.** Each amount is a CSS custom property, such
  as `--tones-medium-surface`, so changing a strength never touches a
  component. See [custom tones](#custom-tones).

## Roles

A tone draws one of two amounts, and the property you set decides which.

- **Surface** is the lighter amount, for areas: backgrounds and fills.
- **Line** is the stronger amount, for edges and marks that need to stay visible
  at a low opacity: borders, outlines, text, strokes, carets, decoration,
  shadows and column rules.

| Amount | Props | Default range |
| --- | --- | --- |
| Surface | `bg`, `fill`, `accentColor`, and every colour prop not in the line row | 4% to 18% |
| Line | `borderColor` (and per side), `outlineColor`, `color`, `webkitTextFillColor`, `stroke`, `caretColor`, `textDecorationColor`, `boxShadow`, `textShadow`, `columnRuleColor` | 22% to 58% |

<RoleSpecimens />

```tsx
import { Div, Span } from '@reference-ui/react'

// Surface: bg takes the 18% amount.
<Div bg="blue.500/strong" />

// Line: borderColor takes the 58% amount.
<Div borderWidth="2px" borderStyle="solid" borderColor="blue.500/strong" />

// Line: text takes the 58% amount too.
<Span color="blue.500/strong">Accent label</Span>
```

The same tone reads differently by role: `strong` is 18% as a background and 58%
as a border or as text. Text takes the line amount, so use a shade such as
`blue.700` for body copy and keep tones for accents.

In open mode a numeric suffix such as `blue.500/50` still works for a one-off
opacity. Prefer a tone, so one change retunes every use.

## Intensity

Four strengths, from the faintest wash to the most emphatic. Each tile fills with
the surface amount and draws its edge with the line amount, on a light page and
on a dark one.

<IntensityGrid />

```tsx
import { Div, css } from '@reference-ui/react'

const firm = css({ bg: 'blue.500/firm', borderColor: 'blue.500/firm' })

<Div colorMode="dark" bg="docsPageBg">
  <Div className={firm} height="12r" borderWidth="1px" borderStyle="solid" />
</Div>
```

Start at `medium`. Move up when a surface has to be found, and down when it
competes with the content around it.

## Custom tones

Tones are tokens. Add one, or change a default, with `tokens({ tones })`:

```ts
import { tokens } from '@reference-ui/system'

tokens({
  tones: {
    // A flat leaf serves both roles: 6% as a surface and as a line.
    hush: { value: '6%' },
    // Splitting the roles overrides a default.
    medium: { surface: { value: '12%' }, line: { value: '30%' } },
  },
})
```

Each value must be a percentage written `<number>%`, and a leaf can carry a dark
override like any other token. Then use the tone by name, as in
`bg="blue.500/hush"`.

A misspelt tone is caught. A bare `bg="blue.500/mediun"` warns with
`ATM-W-UNKNOWN-TONE`, suggests `medium` and paints the raw value. Inside braces,
as in `border: '1px solid {colors.blue.500/mediun}'`, it is an error and that
colour is dropped.

A tone compiles to a `color-mix` over one custom property per role. A flat tone
such as `hush` has a single property, `--tones-hush`.

```css
color-mix(in srgb, var(--colors-blue-500) var(--tones-medium-surface), transparent)
```

## Composition

Base is the shade at full strength. Medium and strong are the same shade at a
tone. A tone can paint a background, a border, a graph fill or a foreground; only
the role and the strength change.

<ColorComposition />

Each step is one class that sets two props. `bg` takes the surface amount and
`borderColor` takes the line amount, so one tone gives a tint and a matching
edge.

```tsx
import { css } from '@reference-ui/react'

const surfaceMedium = css({
  bg: 'blue.500/medium',
  borderColor: 'blue.500/medium',
})
```

## Choosing a strength

The job decides which strength fits, so the same blue can be a resting surface, a
selection, a data fill or an accent edge.

| Role | Medium | Strong |
| --- | --- | --- |
| Backgrounds | A quiet tinted surface | A selected or emphasised surface |
| Borders | A faint outline | A soft accent outline |
| Hover states | A gentle wash | A clearer highlight |
| Shadows and glows | Ambient colour | A stronger glow |
| Graph fills | A light area under a line | An emphasised data region |
| Overlays | A light wash over content | A stronger overlay |
| Text | Too faint for copy | An accent label, never body copy |
| Icons | Too faint | Only an accent icon |

<RoleCases />

```tsx
import { css } from '@reference-ui/react'

const selected = css({ bg: 'blue.500/strong', borderColor: 'blue.500/strong' })
const graphFill = css({ fill: 'blue.500/medium' })
const accentEdge = css({ borderColor: 'blue.500/strong' })
```

## Complementary accents

Start from a blue surface and keep most of the foreground blue. Give the one
thing that should stand out an accent from the far side of the wheel.

<ComplementaryCards />

Amber sits almost opposite blue, so the pair reads as warm against cool. Use it
sparingly: one marker or one meter, not every element.

```tsx
import { Div } from '@reference-ui/react'

<Div
  bg="blue.500/medium"
  borderColor="blue.500/medium"
  borderWidth="1px"
  borderStyle="solid"
>
  <Div bg="amber.500" width="3r" height="3r" borderRadius="full" />
</Div>
```

## The four relationships

Four ways to pair an accent with blue, by where the accent sits on the wheel.

<RelationshipGrid />

```tsx
import { Div } from '@reference-ui/react'

<Div bg="blue.400" />    {/* the source */}
<Div bg="blue.800" />    {/* monochromatic */}
<Div bg="violet.500" />  {/* analogous */}
<Div bg="amber.500" />   {/* complementary */}
<Div bg="orange.500" />  {/* split complementary, with lime.500 */}
```

## Enforcing tokens

Open mode, the default, accepts any colour. Strict mode narrows colour props to
your tokens. Turn it on in `ui.config.ts`:

```ts
import { defineConfig } from '@reference-ui/neo'

export default defineConfig({
  name: 'my-app',
  include: ['src/**/*.{ts,tsx}'],
  strict: ['colors'],
})
```

`strict` takes any of `'colors'`, `'radii'` and `'spacing'`. Any other value
throws when the config loads.

With `colors` on, colour props accept only a colour token (`blue.500`), a tone
(`blue.500/medium`), or one of the keywords `white`, `black`, `inherit`,
`currentColor` and `transparent`. Non-colour props stay open. The check covers
your own code: JSX props, `css()` and the `css` prop. It does not narrow the props
of components from `@reference-ui/lib`.

```tsx
import { Div } from '@reference-ui/react'

// Accepted: a colour token, a tone, or a keyword.
<Div bg="blue.500/medium" color="currentColor" />

// Type errors: a raw opacity, a hex value, an unknown name.
<Div bg="blue.500/50" />
<Div bg="#3b82f6" />
<Div bg="not-a-token" />
```

Leave `strict` out to keep open mode, where `blue.500/50` and any CSS colour still
work. The check runs at the type level, so it shows up in your editor and in
`tsc`.

## Palette

The palette is one ramp per colour family, from `50` (the lightest step) to `950`
(the darkest). Each step is a shade: a fixed colour you can name in any colour
prop. For a colour at a strength rather than a fixed step, use a
[tone](#shades-and-tones).

### Neutrals

Slate and gray are the neutrals. Use them for surfaces, rules and body text, and
let the hues carry the meaning.

### Hues

Seventeen families, from red through rose. Each is a full ramp, from `50` to
`950`.

<PaletteDemo group="hues" />

### In use

Name a shade by its family and step. The same name works in every colour prop.

```tsx
import { Div, P } from '@reference-ui/react'

<Div bg="blue.100" borderColor="blue.300">
  <P color="blue.900">A light blue surface with a deep blue label.</P>
</Div>
```

## Light & Dark Mode

Theme-aware tokens resolve to different values without swapping components or
styles. Toggle the preview scope: the same token names (`docsPageBg`,
`docsText`, `docsBorder`, …) drive both modes.

<ColorModeDemo />

### How it works

Scoping is set with the `colorMode` prop on a primitive, which writes the mode
to the subtree. Tokens defined with a `dark` override then resolve accordingly —
the markup is identical in both modes.

```tsx
import { Div, P } from '@reference-ui/react'

<Div colorMode="dark" bg="docsPageBg" color="docsText">
  <P color="docsMuted">Muted copy that adapts to the scope.</P>
</Div>
```

The docs shell uses a single toggle that sets this at the root, so every page
and every component inherits the active mode.
