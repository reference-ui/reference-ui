# Color

`@reference-ui/lib` ships three layers of color tokens:

- **A palette** of 19 color families, each a ramp of 11 shades from `50` to
  `950`.
- **Four tones**, `ghost`, `medium`, `firm` and `strong`, that put any shade at a
  named strength.
- **Semantic tokens**, such as `design.background` and `design.text.base`, that
  hold one value for light mode and one for dark mode.

You write all three as plain values in color props: `bg="blue.500"`,
`bg="blue.500/medium"`, `color="design.text.base"`. Each is defined with
`tokens()`, which [Tokens](/tokens) explains.

## Palette

Each family is a ramp of fixed steps: `50`, `100`, then every hundred to `900`,
then `950`. `50` is the lightest step and `950` the darkest. A step is a
**shade**. Every value is an `oklch()` color, and a shade is the same in light
and dark mode.

Name a shade by family and step. The name works in every color prop.

```tsx
import { Div, P } from '@reference-ui/react'

<Div bg="blue.100" borderColor="blue.300">
  <P color="blue.900">A light blue surface with a deep blue label.</P>
</Div>
```

### Neutrals

`slate` and `gray` are the neutrals. Lib builds most of its own surfaces, borders and
text from `gray`.

### Hues

Seventeen families, in this order: `red`, `orange`, `amber`, `yellow`, `lime`,
`green`, `emerald`, `teal`, `cyan`, `sky`, `blue`, `indigo`, `violet`,
`purple`, `magenta`, `pink` and `rose`.

## Tones

A **tone** is a shade at a named strength, written `shade/tone`:
`blue.500/medium` is `blue.500` at the medium strength. The tone mixes the shade
with transparency, so the result takes on whatever sits behind it: a pale wash
on a light page and a dim glow on a dark one, with no separate dark value.

<ShadesAndTones />

```tsx
import { Div } from '@reference-ui/react'

// A shade: the solid step.
<Div bg="blue.500" />

// A tone: the same shade at the medium strength.
<Div bg="blue.500/medium" />
```

### Tone values

Each tone holds two amounts. The **surface** amount paints areas. The **line**
amount is stronger, so edges and text stay visible.

| Tone | Surface | Line |
| --- | --- | --- |
| `ghost` | 4% | 22% |
| `medium` | 10% | 34% |
| `firm` | 14% | 46% |
| `strong` | 18% | 58% |

<IntensityGrid />

### Surface and line

The prop you set decides which amount a tone draws. Border and outline props,
`color`, text decoration, strokes and shadows draw the line amount. Every other
color prop, including `bg` and `fill`, draws the surface amount.
[Tokens](/tokens) covers how roles resolve.

<RoleSpecimens />

```tsx
import { Div, Span } from '@reference-ui/react'

// Surface: bg takes the 18% amount.
<Div bg="blue.500/strong" />

// Line: borderColor takes the 58% amount.
<Div borderWidth="2px" borderStyle="solid" borderColor="blue.500/strong" />

// Line: text takes the 58% amount too.
<Span color="blue.500/strong">Accent label</Span>
```

Start at `medium`. Move up when a surface has to stand out, and down when it
competes with the content around it. Use a shade such as `blue.700`, not a tone,
for body text.

To add a tone or change these amounts, define `tones` in your own `tokens()`
call; see [Tokens](/tokens).

## Semantic tokens

Semantic tokens name a job rather than a color. Each one points at a palette
shade in light mode and another in dark mode, so components that use them
follow the active [color mode](#light-and-dark-mode). Lib's components read
these tokens, and you can use them in your own styles.

| Token | Light | Dark |
| --- | --- | --- |
| `design.background` | `oklch(100% 0 0)` | `gray.950` |
| `design.foreground` | `gray.950` | `gray.50` |
| `design.primary.background` | `gray.950` | `gray.100` |
| `design.primary.foreground` | `gray.50` | `gray.950` |
| `design.primary.hover.background` | `gray.900` | `gray.50` |
| `design.accent.foreground` | `blue.600` | `blue.300` |
| `design.accent.background` | `gray.100` | `gray.950` |
| `design.accent.hover` | `blue.800` | `blue.300` |
| `design.accent.border` | `gray.300` | `blue.950` |
| `design.text.base` | `gray.950` | `gray.50` |
| `design.text.light` | `gray.700` | `gray.300` |
| `design.text.lighter` | `gray.600` | `gray.400` |
| `design.mark.background` | `blue.200` | `blue.950` |
| `design.mark.foreground` | `blue.950` | `blue.200` |
| `design.positive.text` | `green.600` | `green.400` |
| `design.bg.muted` | `gray.100` | `gray.900` |

```tsx
import { Div, P } from '@reference-ui/react'

<Div bg="design.background" color="design.text.base">
  <P color="design.text.light">Secondary copy that follows the color mode.</P>
</Div>
```

Lib also defines two narrower groups:

- `text.*`: `text.primary`, `text.secondary`, `text.disabled`, `text.accent`
  and `text.highlight`.
- `ui.*`: one group per element, such as `ui.link.default`, `ui.button.hover`
  and `ui.focus.ring`. Lib's primitives and components style themselves with
  these. Each is named for one element, so prefer `design.*` in your own code.

## Light and dark mode

Light mode is the default. Dark mode applies when an element, or one of its
ancestors, carries `data-color-mode="dark"`. Lib's stylesheet does not read the
operating system's `prefers-color-scheme` setting; your app decides the mode.

Set the mode for a subtree with the `colorMode` prop on any primitive. The
markup and token names stay the same; only the resolved values change.

<ColorModeDemo />

```tsx
import { Div, P } from '@reference-ui/react'

<Div colorMode="dark" bg="design.background" color="design.text.base">
  <P color="design.text.light">Copy that resolves to its dark values.</P>
</Div>
```

To switch the whole page, set `colorMode` on your root element, or set
`data-color-mode="dark"` on `<html>` or `<body>`.

Only semantic tokens change between modes. Shades are fixed, and a tone adapts
because it is see-through, not because it has a dark value.
