# Color

Lib ships a colour palette, four tones and a set of semantic tokens for light
and dark mode.

All three work in any colour prop: `bg="blue.500"`, `bg="blue.500/medium"`,
`color="design.text.base"`.

## Palette

The palette has 19 families. Each is a ramp of 11 shades: `50`, `100`, every
hundred to `900`, then `950`. `50` is the lightest and `950` the darkest. Every
shade is an `oklch()` colour, and it is the same in light and dark mode.

```tsx
import { Div, P } from '@reference-ui/react'

<Div bg="blue.100" borderColor="blue.300">
  <P color="blue.900">A light blue surface with a deep blue label.</P>
</Div>
```

### Neutrals

`slate` and `gray` are the neutrals. Most of lib's surfaces, borders and text
use `gray`.

## Tones

A tone is a shade at a named strength, written `shade/tone`. The tone mixes
the shade with transparency, so it takes on whatever sits behind it. It needs
no separate dark value.

<ShadesAndTones />

```tsx
import { Div } from '@reference-ui/react'

// A shade: the solid step.
<Div bg="blue.500" />

// A tone: the same shade at medium strength.
<Div bg="blue.500/medium" />
```

Each tone holds two amounts. The surface amount paints areas. The line amount
is stronger, so edges and text stay visible.

| Tone | Surface | Line |
| --- | --- | --- |
| `ghost` | 4% | 22% |
| `medium` | 10% | 34% |
| `firm` | 14% | 46% |
| `strong` | 18% | 58% |

<IntensityGrid />

The prop determines which amount a tone uses. `border*` and `outline*` props,
`color`, text decoration, strokes and shadows use the line amount; every other
colour prop, including `bg` and `fill`, uses the surface amount.

<RoleSpecimens />

Start at `medium`. Go up when a surface has to stand out, and down when it
competes with the content around it. For body text, use a shade such as
`blue.700`, not a tone.

## Semantic tokens

A semantic token names a job, not a colour. Each one has a light value and a
dark value, so it follows the [colour mode](#light-and-dark-mode). Lib's
components use these tokens, and so can your styles.

| Token | Light | Dark |
| --- | --- | --- |
| `design.background` | `oklch(100% 0 0)` | `gray.950` |
| `design.foreground` | `gray.950` | `gray.50` |
| `design.primary.background` | `gray.950` | `gray.100` |
| `design.primary.foreground` | `gray.50` | `gray.950` |
| `design.primary.hover.background` | `gray.900` | `gray.50` |
| `design.accent.foreground` | `blue.600` | `blue.300` |
| `design.accent.background` | `gray.100` | `gray.950` |
| `design.accent.hover` | `blue.800` | `blue.300` |
| `design.accent.border` | `gray.300` | `blue.950` |
| `design.text.base` | `gray.950` | `gray.50` |
| `design.text.light` | `gray.700` | `gray.300` |
| `design.text.lighter` | `gray.600` | `gray.400` |
| `design.mark.background` | `blue.200` | `blue.950` |
| `design.mark.foreground` | `blue.950` | `blue.200` |
| `design.positive.text` | `green.600` | `green.400` |
| `design.bg.muted` | `gray.100` | `gray.900` |

```tsx
import { Div, P } from '@reference-ui/react'

<Div bg="design.background" color="design.text.base">
  <P color="design.text.light">Secondary copy that follows the colour mode.</P>
</Div>
```

Lib also defines `ui.*`, one group per element, such as `ui.link.default`,
`ui.button.hover` and `ui.focus.ring`. Lib's primitives and components style
themselves with these. Prefer `design.*` in your own code.

`text.*` (`text.primary`, `text.secondary` and three more) is defined too, but
nothing in lib reads it. Use `design.text.*`.

## Light and dark mode

Light mode is the default. Dark mode applies inside an element that carries
`data-color-mode="dark"`. Lib's tokens don't read the operating system's
`prefers-color-scheme` setting: your app picks the mode.

Set the mode for a subtree with the `colorMode` prop on any primitive. The
token names stay the same and only their values change.

<ColorModeDemo />

```tsx
import { Div, P } from '@reference-ui/react'

<Div colorMode="dark" bg="design.background" color="design.text.base">
  <P color="design.text.light">Copy that resolves to its dark values.</P>
</Div>
```

To switch the whole page, set `colorMode` on your root primitive.
[Light and dark](/light-and-dark) covers following the system setting and adding a
toggle, and [Server-side rendering](/ssr) covers setting the mode from the request.

Only semantic tokens change between modes. Shades stay fixed, while tones
blend with the surface behind them.
