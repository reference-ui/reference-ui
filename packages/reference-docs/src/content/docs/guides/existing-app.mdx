# Add to an existing app

Reference UI works alongside your existing CSS, so you can migrate an
application one screen or feature at a time.

<Step n={1}>Install and initialize</Step>

Follow steps 1 and 2 of [Getting started](/initialize): install the
packages, run `ref init`, then `ref sync`.

<Step n={2}>Start with one feature</Step>

`ref sync` only scans files matched by `include`. Scope it to the first
feature you are migrating:

```ts
// ui.config.ts
import { defineConfig } from '@reference-ui/core'
import { baseSystem } from '@reference-ui/lib/baseSystem'

export default defineConfig({
  name: 'my-app',
  include: ['src/features/settings/**/*.{ts,tsx}'],
  extends: [baseSystem],
  normalizeCss: false,
})
```

Files outside `include` are not scanned by the compiler.

Setting `normalizeCss: false` disables the default CSS reset (`box-sizing: border-box`
on all elements, zeroed margins on `body`, `h1` through `h4`, and `p`, and
block-level images), preserving the appearance of unmigrated screens.

<Step n={3}>Import the stylesheet</Step>

Import the generated stylesheet in your app entry beside your existing CSS:

```tsx
// src/main.tsx
import '@reference-ui/react/styles.css'
```

## CSS cascade and specificity

Reference UI places all generated rules inside CSS cascade layers. Because
unlayered CSS always takes precedence over layered CSS regardless of
specificity or load order, your existing unlayered styles will override
Reference UI rules when both target the same element.

The library's global styles target primitive classes such as `ref-button`,
leaving existing markup unaffected except for two bare element selectors:

- `body` sets the default font family, font size, letter spacing, and
  `container-type: inline-size`.
- `code` sets the inline code monospace font, background, border, and
  padding.

Any unlayered rules you have for `body` or `code` continue to take precedence.

If a migrated screen inherits unintended styles from your legacy stylesheet,
either remove the legacy selector once it is no longer needed, or wrap your
existing CSS in a cascade layer declared before Reference UI's layers (see
[Cascade layers](/cascade-layers#your-own-css)).

If your existing CSS already uses `@layer`, CSS gives lower precedence to
whichever layer is declared first. To control the layer order explicitly,
declare all layer names in a single `@layer` statement before importing either
stylesheet. Reference UI uses `root` plus one layer per system (see
[One layer per system](/cascade-layers#one-layer-per-system)).

## Completing the migration

1. Convert a screen to primitives and library components.
2. Expand `include` to cover the new files and run `ref sync`.
3. Remove the legacy CSS rules that the screen no longer uses.

Once the migration is complete, remove `normalizeCss: false` to enable the
default CSS reset.
