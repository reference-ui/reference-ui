# Add to an existing app

Reference UI runs beside your existing CSS, so you can move an app over one
screen at a time.

<Step n={1}>Install and initialize</Step>

Follow steps 1 and 2 of [Getting started](/initialize): install the
packages, run `ref init`, then `ref sync`.

<Step n={2}>Start with one feature</Step>

Sync compiles only the files `include` matches. Point it at the first
feature you move:

```ts
// ui.config.ts
import { defineConfig } from '@reference-ui/core'
import { baseSystem } from '@reference-ui/lib/baseSystem'

export default defineConfig({
  name: 'my-app',
  include: ['src/features/settings/**/*.{ts,tsx}'],
  extends: [baseSystem],
  normalizeCss: false,
})
```

Style props and `css()` calls in files outside `include` get no CSS.

`normalizeCss: false` turns off the CSS reset. The reset sets
`box-sizing: border-box` on every element, removes the margins on `body`,
`h1` to `h4` and paragraphs, and makes images block elements. With it off,
screens you haven't moved keep their look.

<Step n={3}>Import the stylesheet</Step>

```tsx
// src/main.tsx
import '@reference-ui/react/styles.css'
```

## How the two stylesheets meet

Every Reference UI rule sits in a cascade layer. In CSS, any unlayered rule
beats every layered rule, whatever its specificity or load order. Most
existing CSS is unlayered, so where both style the same element, your
existing styles win.

The library's global CSS targets primitives by their `ref-` classes, such
as `ref-button`, so it leaves most of your existing markup alone. Two element
selectors are the exception:

- `body` gets the font family, letter spacing, font size and
  `container-type: inline-size`.
- `code` gets the inline code style: monospace font, background, border and
  padding.

A rule of your own for either element still wins for each property it sets.

If a converted screen still shows its old styles, an old selector is
reaching it. Delete that rule once nothing else needs it. To let converted
screens win instead, move the old CSS into a layer declared before the
stylesheet, as [Cascade layers](/cascade-layers#your-own-css) shows.

If your existing CSS uses cascade layers of its own, the layer whose name
appears first ranks lowest, so import order decides between the two. To
fix the order, declare every layer name in one `@layer` statement at the
top of a stylesheet that loads before both. Reference UI's layer names are
`root` and one per system, listed in
[One layer per system](/cascade-layers#one-layer-per-system).

## Move over

1. Convert a screen to primitives and library components.
2. Widen `include` to cover it, and run `ref sync`.
3. Delete the old CSS it no longer uses.

Once nothing depends on the old styles, remove `normalizeCss: false` to turn
the reset back on.
