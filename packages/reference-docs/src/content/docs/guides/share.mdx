# Share a design system

Design systems in Reference UI chain: one package publishes its system, and
an app builds on it. `@reference-ui/lib` is shared this way.

<Step n={1}>Build the system</Step>

A design system is a package with its own `ui.config.ts`. Define its tokens
as in [Theming](/theming), and its components as in
[Build a component](/build-a-component). Its `name` identifies it in every
app that uses it.

<Step n={2}>Export the base system</Step>

`ref sync` writes your system to `.reference-ui/system/baseSystem.mjs`.
Export it, and list it in `files` so it gets published:

```json
{
  "exports": {
    "./baseSystem": {
      "types": "./.reference-ui/system/baseSystem.d.mts",
      "import": "./.reference-ui/system/baseSystem.mjs"
    }
  },
  "files": [
    "dist",
    ".reference-ui/system/baseSystem.d.mts",
    ".reference-ui/system/baseSystem.mjs"
  ]
}
```

The base system carries:

- your tokens, fonts and keyframes, as definitions the app's sync reads;
- the styles your sync compiled, global CSS and recipes included;
- your components' names, and the props each one keeps for itself.

Your `recipe()` definitions don't travel. The app receives their compiled
classes, not the recipe configs, so each recipe stays as your sync built it.

The app's sync builds its stylesheet from the base system, so you don't
export a stylesheet.

<Step n={3}>Build the package</Step>

Run `ref sync` before you build. The app never syncs your source, so your
components' styles come only from your sync. A `prepack` script keeps the
published files current:

```json
{
  "scripts": {
    "prepack": "ref sync && npm run build"
  }
}
```

Bundle `@reference-ui/react` into your build output, and leave it out of
`dependencies` and `peerDependencies`. Your sync generates it bound to your
system's `name`, so your components render under your name in any app. Keep
`react` as a peer dependency so the app supplies a single copy.

<Step n={4}>Build on it in an app</Step>

Import the base system in the app's config and add it to `extends`:

```ts
// ui.config.ts
import { defineConfig } from '@reference-ui/core'
import { baseSystem } from 'my-design-system/baseSystem'

export default defineConfig({
  name: 'my-app',
  include: ['src/**/*.{ts,tsx}'],
  extends: [baseSystem],
})
```

Run `ref sync` in the app. The app still imports only
`@reference-ui/react/styles.css`; your system's styles are part of it.

## `extends` or `layers`

| | `extends` | `layers` |
| --- | --- | --- |
| Your styles reach the app | yes | yes |
| Your tokens join the app's types | yes | no |
| Where the app and your system set the same token | the app's value wins, inside your components too | your components keep your value |

Use `extends` when the app builds on your system. Use `layers` when the app
only renders your components and keeps its own tokens.

## Style your components from the app

Either way, the app styles your components like its own, with style props
and its tokens:

```tsx
import { Card } from 'my-design-system'

<Card padding="6r" bg="surface" />
```

Props your component reads itself, such as `tone`, stay its own. Nothing
needs registering in either package.

If your system is in neither the app's `extends` nor its `layers`, the style
props don't paint, and `ref sync` warns `ATM-W-EXTERNAL-UNBACKED` at the
component, naming your package. Another system in `extends` or `layers`
doesn't stand in for yours.

## In a monorepo

A design system in the same repository as the app needs no publishing.
Sync follows each import to the files it lands on. Pick one of two shapes.

**One system.** Run one sync at the repository root, with `include`
covering the app and the package. The package's components become part of
the app's system, and their style props compile like the app's own:

```ts
// ui.config.ts at the repository root
import { defineConfig } from '@reference-ui/core'

export default defineConfig({
  name: 'my-app',
  include: ['apps/web/src/**/*.{ts,tsx}', 'packages/ui/src/**/*.{ts,tsx}'],
})
```

**Two systems.** The package runs its own sync and exports its system as
above, and the app adds it to `extends` or `layers`. Its components render
with the package's system, as a published package's do. Once the package
has its own sync output, sync uses this shape, even if the app's `include`
also covers the package's source.
