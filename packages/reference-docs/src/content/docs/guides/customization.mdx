# Customization

This guide shows how to customize Reference UI's primitives, the components
in `@reference-ui/lib`, and components from other libraries:

- **Style props**: one instance.
- **Global CSS**: every primitive of one kind.
- **Tokens**: every component that uses the token.
- **`css()`**: components from other libraries.

To decide between style props, `css()` and recipes for your own components,
see [Choose a styling API](/choose-a-styling-api).

## Style props

Style props on a library component land on its outermost element, so you
can change one button and leave the rest alone:

<Preview>
  <StylePropsDemo />
</Preview>

```tsx
<Button
  variant="primary"
  bg="blue.600"
  color="white"
  borderRadius="full"
  paddingInline="5r"
>
  Save changes
</Button>
```

## Global CSS

Each primitive includes a class named after its tag, such as `ref-button`,
`ref-input` and `ref-a`. The names are stable, so you can style every
primitive of one kind with `globalCss()`, without a class of your own:

<Preview>
  <GlobalCssDemo />
</Preview>

```ts
// src/theme/global.ts
import { globalCss } from '@reference-ui/system'

globalCss({
  '.ref-button': {
    borderRadius: '0',
    fontSize: '3r',
    textTransform: 'uppercase',
    letterSpacing: '0.08em',
  },
})
```

The `variant` prop sets `data-variant` on the element, so a rule can target
one variant with a selector such as `.ref-button[data-variant="primary"]`.
To reach the inner parts of a compound component, see
[Multi-part components](/multi-part-components).

Your global CSS sits in a later [cascade layer](/cascade-layers) than the
library's, so it wins. Style props sit in a later layer than global CSS, so
they still override it on one element.

## Extend the library's tokens

The library styles its components with its own tokens, such as
`colors.ui.button.background`. Change a token's value and every component
that uses it changes too.

### Create a branded copy

`extendSystem()` takes the library's base system and your token values, and
returns a branded copy:

```ts
// src/theme/brand.ts
import { extendSystem } from '@reference-ui/core'
import { baseSystem } from '@reference-ui/lib/baseSystem'

export const brandedLib = extendSystem(baseSystem, {
  tokens: {
    colors: {
      ui: {
        button: {
          background: { light: '#0f766e', dark: '#5eead4' },
          hover: { light: '#115e59', dark: '#99f6e4' },
        },
      },
    },
  },
})
```

### Add it to your config

Put the branded copy in `extends`, where `ref init` put the library:

```ts
// ui.config.ts
import { defineConfig } from '@reference-ui/core'
import { brandedLib } from './src/theme/brand'

export default defineConfig({
  name: 'my-app',
  include: ['src/**/*.{ts,tsx}'],
  extends: [brandedLib],
})
```

Every primary button picks up your values, so `<Button variant="primary">`
turns teal.

### Token values

You can only change tokens the library declares. An unknown token path, or a
reference to one, makes `extendSystem()` throw. To add tokens of your own,
use `tokens()`: see [Theming](/theming).

A token takes `value`, or `light` and `dark`. A token with no `dark` value
uses its light value in both modes. A value can point at another library
token with `{colors.gray.950}`.

## Other libraries

Any component that accepts `className` can take a `css()` class, including
components from libraries not built with Reference UI:

```tsx
import { css } from '@reference-ui/react'

<DatePicker className={css({ padding: '2r', borderRadius: 'md' })} />
```
