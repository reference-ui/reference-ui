# Troubleshooting

Most styling issues come down to whether `ref sync` extracted your style. Check
the sync output first, then match your symptom below.

## Check sync warnings

By default, `ref sync` summarizes warnings as a count. Run `--verbose` to print
each warning with its file location and fix hint:

```bash
npx ref sync --verbose
```

To include compiler warnings for dynamic values and spreads that couldn't be
statically extracted, enable the `compiler` log channel in `ui.config.ts`:

```ts
// ui.config.ts
export default defineConfig({
  name: 'my-app',
  include: ['src/**/*.{ts,tsx}'],
  logs: ['compiler'],
})
```

See [Diagnostics](/diagnostics#where-they-appear) for `--json` output and every
warning code.

## No styles at all

- **Stylesheet not imported.** Import the generated stylesheet once at your app
  entry:
  ```tsx
  // src/main.tsx
  import '@reference-ui/react/styles.css'
  ```
- **Sync hasn't run.** Run `npx ref sync` and check that `.reference-ui/`
  exists. See [Sync](/sync#verify-the-output).

## New styles don't appear

Styles added after the last sync won't have CSS until sync runs again. Run
`ref sync --watch` alongside your dev server so changes compile automatically.
See [Sync](/sync).

## One file's styles are missing

Sync only scans files matched by `include` in `ui.config.ts`. Check that the
file path matches your globs. A pattern that matches nothing warns with
`include matched no files`.

## One property is missing

- **Dynamic value at runtime.** The compiler extracts styles statically without
  running your code, so runtime values get no CSS unless pre-generated. In
  development, the browser console warns `css(): no compiled class for` the
  missing property and value. Use conditional static values, a recipe, CSS
  variables or `staticCss`. See [Dynamic styles](/dynamic-styles).
- **Wrong `css()` import.** Only `css()` and `recipe()` imported from
  `@reference-ui/react` or `@reference-ui/styled` are compiled. Local functions
  or imports from other packages are ignored.

## A recipe resolves to nothing

Check the browser console warning:

- **`needs a literal className`**: pass a string literal `className` to
  `recipe()`. See [Recipes](/recipes).
- **`no compiled table found`**: the recipe was added after the last sync. Run
  `ref sync`.

## A recipe that nothing calls emits no CSS

Sync only emits CSS for recipes that are called in your `include` files. An
uncalled recipe (or one only called indirectly through a map, prop or `.raw()`)
emits no rules. Call the recipe directly in a matched source file. See
[Recipes](/recipes).

## Style props on a package component have no effect

Components from an external package only accept style props when that package's
`baseSystem` is listed in `extends` or `layers`. Add the `baseSystem` named in
the sync warning. See [Primitives](/primitives#your-own-components).

## Another rule wins

Every Reference UI rule lives in a `@layer`. Standard unlayered CSS always
overrides layered rules regardless of specificity. Remove the competing
unlayered rule, or wrap your custom stylesheet in a layer declared before
Reference UI's stylesheet. See [Cascade layers](/cascade-layers#your-own-css).

Within Reference UI, style props and `css()` classes always override recipes
and `globalCss()` rules on the same element.
