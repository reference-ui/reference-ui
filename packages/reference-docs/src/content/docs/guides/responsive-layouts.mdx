# Responsive layouts

Responsive styles in Reference UI use CSS container queries, adapting to the
width of the nearest container rather than the viewport. Components respond to
their available width whether rendered in a full page, a sidebar, or a dialog.

<Step n={1}>Ensure the root container is defined</Step>

`@reference-ui/lib` sets `container-type: inline-size` on `body` by default. If
your config does not extend `@reference-ui/lib`, define a root container in your
global CSS:

```ts
// src/theme/global.ts
import { globalCss } from '@reference-ui/system'

globalCss({
  body: { containerType: 'inline-size' },
})
```

Container queries require an ancestor container to match; `ref sync` emits a
warning if no container is defined in your global CSS.

<Step n={2}>Change values at breakpoints</Step>

Pass an object with a value per breakpoint. `base` applies at every width,
and each breakpoint applies from its width up:

```tsx
<Div
  display="grid"
  gap={{ base: '3r', md: '6r' }}
  gridTemplateColumns={{ base: '1fr', md: 'repeat(2, 1fr)', xl: 'repeat(4, 1fr)' }}
>
  <Card />
  <Card />
  <Card />
  <Card />
</Div>
```

This renders a single column by default, two columns from `md` (768px), and four
columns from `xl` (1280px). See [Responsive](/responsive) for the full
breakpoint scale.

Define the narrowest layout under `base` and override it at larger breakpoints.
Because `sm` starts at 640px, containers narrower than 640px only match `base`.

<Step n={3}>Show and hide by width</Step>

Switch `display` between `none` and a layout value at a breakpoint:

```tsx
<Nav display={{ base: 'none', md: 'flex' }}>…</Nav>
<Button display={{ md: 'none' }}>Menu</Button>
```

To restrict a style to a specific width range, use a range key such as `mdOnly`
or `smToLg` (see [Responsive](/responsive#target-a-range)).

## Nested containers

Add the `container` prop to any primitive so responsive styles inside it
measure that element's width instead of `body`:

```tsx
<Div display="grid" gridTemplateColumns="16rem 1fr">
  <Aside container>
    <ProfileCard />
  </Aside>
  <Main container>
    <ProfileCard />
  </Main>
</Div>
```

The same `ProfileCard` component renders its compact layout in the `16rem`
sidebar and its expanded layout in the main column.

To query a specific ancestor container instead of the nearest one, pass a
container name to `container` and reference it in the `r` prop:

```tsx
<Main container="content">
  {/* … */}
  <Div r={{ 'content/md': { padding: '8r' } }} />
</Main>
```

`'content/md'` matches when the container named `content` is at least
768px wide.

## Switch a recipe variant

A recipe variant takes the same breakpoint object:

```tsx
<button className={button({ size: { base: 'sm', md: 'lg' } })}>Save</button>
```

The button is `sm` until its container reaches `md`, then `lg`.
[Recipes](/recipes#responsive-variants) covers how compound variants treat
these values.
