# Multi-part components

Some components are more than one element. A card has a root, a title and a
body, and one `size` prop should style every part.

A recipe with `slots` styles every part from one call: it returns one class
per part. A `data-slot` attribute names a part, so a rule on another element
can reach it.

## Your own component

<Step n={1}>Define the slots</Step>

List the parts in `slots`, then key `base` and each variant value by part:

```tsx
// src/components/Card.tsx
import { recipe } from '@reference-ui/react'

const card = recipe({
  className: 'card',
  slots: ['root', 'title', 'body'],
  base: {
    root: { display: 'flex', flexDirection: 'column', borderRadius: 'md' },
    title: { margin: '0', fontWeight: '600' },
    body: { margin: '0', opacity: 0.8 },
  },
  variants: {
    size: {
      sm: { root: { padding: '3r', gap: '1r' }, title: { fontSize: '4r' } },
      lg: { root: { padding: '6r', gap: '2r' }, title: { fontSize: '5r' } },
    },
  },
  defaultVariants: { size: 'sm' },
})
```

A part that a variant does not name, like `body` here, keeps its base styles.

<Step n={2}>Give each part its class</Step>

Call the recipe once and pass each part its class. A `data-slot` on each part
names it for the next step:

```tsx
// src/components/Card.tsx
import { Div, H3, P, type DivProps } from '@reference-ui/react'

type CardProps = DivProps & { size?: 'sm' | 'lg'; heading: string }

export function Card({ size = 'sm', heading, children, ...props }: CardProps) {
  const classes = card({ size })
  return (
    <Div data-slot="root" {...props} className={classes.root}>
      <H3 data-slot="title" className={classes.title}>{heading}</H3>
      <P data-slot="body" className={classes.body}>{children}</P>
    </Div>
  )
}
```

<Step n={3}>Style a part from the root</Step>

Some styles depend on another part's state. An `&` selector in the root's
styles reaches a part by its `data-slot`. Here the title underlines while the
card is hovered:

```tsx
base: {
  root: {
    display: 'flex',
    flexDirection: 'column',
    borderRadius: 'md',
    '&:hover > [data-slot="title"]': { textDecoration: 'underline' },
  },
  // title and body as before
},
```

`Tree.Item` uses the same selector to draw its focus ring on its row:
`'&:focus-visible > [data-slot="row"]'`.

### Usage

```tsx
<Card heading="Starter">One project.</Card>
<Card size="lg" heading="Team">Every project in one place.</Card>
```

## A library component's parts

A `data-slot` attribute is a stable selector, so `globalCss()` can restyle a
part of a library component everywhere. A `Tree.Item` branch wraps its content
in a `[data-slot="row"]` element:

```ts
// src/theme/global.ts
import { globalCss } from '@reference-ui/system'

globalCss({
  '[role="treeitem"] > [data-slot="row"]': {
    fontWeight: '600',
  },
})
```

Your global CSS sits in a later [cascade layer](/cascade-layers) than the
library's, so it wins. Inside your own system, a global rule sits below
recipes and `css()` classes, so it does not override your own parts' styles.

## A headless library's parts

Each part of a headless component, such as Radix's, accepts `className`.
Give each part a `css()` class:

```tsx
import { Accordion } from 'radix-ui'
import { css } from '@reference-ui/react'

const item = css({
  borderBottom: '1px solid {colors.line}',
  _open: { borderBottomWidth: '2px' },
})

const trigger = css({
  display: 'flex',
  justifyContent: 'space-between',
  width: '100%',
  padding: '3r',
  _disabled: { opacity: 0.5 },
})

const content = css({ paddingInline: '3r', paddingBottom: '3r' })

export function Faq() {
  return (
    <Accordion.Root type="single" collapsible>
      <Accordion.Item value="billing" className={item}>
        <Accordion.Header>
          <Accordion.Trigger className={trigger}>Billing</Accordion.Trigger>
        </Accordion.Header>
        <Accordion.Content className={content}>We bill monthly.</Accordion.Content>
      </Accordion.Item>
    </Accordion.Root>
  )
}
```

Headless parts expose their state as data attributes, and named conditions
such as `_open`, `_closed` and `_disabled` match them. See
[Conditions](/conditions#disclosure-and-selection) for the full list.
