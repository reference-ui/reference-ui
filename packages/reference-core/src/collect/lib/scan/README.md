# Fragment discovery scan

Finds the source files that may carry fragments. Glob roots plus import-or-call signals select absolute paths; a fused suffix walk classifies matchable and retainable flags without allocating per candidate, MDX gets a pure sync selection pass that fences off frontmatter and code blocks, and the native single-read scan shares needle regexes with the TS side so match order never drifts. Differential batteries and committed goldens pin the boundary byte-for-byte.

The project listing (`project-files.ts`) is the one enumeration both scanners and the watch matcher share. It walks the root in the Rust walk's sorted order. A directory is entered only when the include globs can still reach it by its path (the liveness test in `project-admission.ts`), and a symlinked directory is entered under every such alias. Under a glob include the walk records each (canonical directory, glob state) it enters, where the state is the set of positions the include's brace alternatives (expanded by `braces.ts`, modeled by `project-globs.ts`) are in after the path, and a directory reached through a link, the link itself or any directory beneath it, is walked only in a state it is not yet walked in, so a loop or a lattice of links ends once its states repeat. A directory reached by real paths alone is always walked. A bracket class opened with `[!` is negated, as in the Rust walk and fast-glob: every picomatch the listing, the include check and the watch matcher build rewrites it to `[^` first (`glob-classes.ts`). A negated include drops the paths it matches; the Rust walk never prunes on one, and this walk prunes a directory or link only where it negates `<dir>/**`, where every path beneath is dropped anyway; ignore globs prune every path they match. Config validation (`include-shapes.ts`) leaves only includes the glob model covers: it reads a paren group as the brace alternation or literal the Rust grammar means (`(a|b)` as `{a,b}`, `(x)` as `[(]x[)]`) and refuses every shape picomatch and Rust read differently, by name and with the form to write, so no validated include takes the loop cut. The native addon, called directly, still reads parens literally. The watch matcher's ownership walk keeps the loop cut: a link whose target is already on the walk path is refused. A file reached through several paths is listed once: under its real path when one exists, otherwise under the first link alias. Include globs that leave the root (`../shared/**`, absolute globs) walk their own base the same way. The watch matcher's ownership walk instead lets the first link per target through, so it is polynomial in the links, and it prunes by the in-root positive include patterns' static prefixes; it is not the modeled walk, and with no in-root positive pattern it does not run. The glob-string helpers the walk reads patterns with (negation, the `./` spelling, a pattern outside the root, the static base, and the picomatch matchers) live in `project-patterns.ts`.

Known limit: the ownership walk and a listing called with an include the model does not cover (a caller outside config validation) keep the per-path loop cut, so a file reached only through a link that closes a loop is not listed for it, and the TS fallback scan (`scanner.ts`), which enumerates through the same listing, has the same limit; such an include never claims a complete walk, so compile's backfill walk still reaches the file. The completeness subset (`isCompleteWalkPattern` in `native.ts`) is narrower than the model on purpose: it keeps the character rule the completeness battery proved, which refuses any paren, pipe, backslash or `[:` even inside a class.
