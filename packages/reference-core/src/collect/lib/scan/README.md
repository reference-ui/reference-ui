# Fragment discovery scan

Finds the source files that may carry fragments. Glob roots plus import-or-call signals select absolute paths; a fused suffix walk classifies matchable and retainable flags without allocating per candidate, MDX gets a pure sync selection pass that fences off frontmatter and code blocks, and the native single-read scan shares needle regexes with the TS side so match order never drifts. Differential batteries and committed goldens pin the boundary byte-for-byte.

The project listing (`project-files.ts`) is the one enumeration both scanners and the watch matcher share. It walks the root in the Rust walk's sorted order. A directory is entered only when the include globs can still reach it by its path (the liveness test in `project-admission.ts`), and a symlinked directory is entered under every such alias, unless its target is already on the walk path, so a loop of links ends at the link that closes it. A file reached through several paths is listed once: under its real path when one exists, otherwise under the first link alias. Include globs that leave the root (`../shared/**`, absolute globs) walk their own base the same way. The watch matcher's ownership walk instead lets the first link per target through.

Known limit: a file reachable within the include only through a link that closes a loop is not listed. With include `src/a/**/*.ts`, the link `src/a/up -> src` leads back to `src`, which the walk already holds on its path, so the walk cuts the link: `src/a/up/x.ts` is never walked, and `src/x.ts` is not listed under any path. Earlier walks refused that link too, so this is an accepted limit, not a regression; listing it needs an alias-aware walk, not the current loop cut.
