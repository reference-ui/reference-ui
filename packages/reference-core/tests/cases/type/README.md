# CORE-TYPE — generated declarations

Proves that after `sync()` the generated declarations type real consumer code: a world importing primitives, `css`/`recipe`, and named types from `@reference-ui/react` compiles clean, token unions and recipe variants reject bad literals, and the system authoring surface typechecks in fragment files. Owns `src/packager/assembly.ts` (types publish only) and `tsconfig.json` `paths`. `SPEC.md` carries the declarations contract; `TESTS.md` is the case ledger.

> Search terms: generated declarations, consumer typecheck, token unions, recipe variants, PrimitiveProps, styled subpaths, authoring surface, strict colours

## Cases

- CORE-TYPE-01 — generated react declarations compile a consumer world.
- CORE-TYPE-02 — token unions are real at ColorToken positions.
- CORE-TYPE-03 — recipe variants are optional literal unions, enforced at the call.
- CORE-TYPE-04 — condition keys and null-hole arrays typecheck.
- CORE-TYPE-05 — the system authoring surface typechecks a fragment file.
- CORE-TYPE-06 — no @pandacss import anywhere in the generated folder.
- CORE-TYPE-07 — styled subpaths and generic PrimitiveProps resolve.
- CORE-TYPE-08 — css() keeps the full key surface on colors-only tokens.
- CORE-TYPE-09 — strict colours reject off-token values on JSX, css() and the css prop.
- CORE-TYPE-10 — lib props follow the consumer's synced system.
