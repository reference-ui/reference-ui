# CORE-LAYERS-04 — container root and upstream qualifiers reach the consumer through layers, as through extends

The consumer authors one container query and carries a local `globalCss` block, so the container-root check has something to judge. The upstream is a real published base system, synced for real by the spec, whose global CSS roots the page with `:root { container-type: inline-size }`. The consumer also renders the upstream package's own `Span` with a literal colour (the probe component): a tag imported from an installed package renders through that package's runtime, so the engine keeps the style prop as an external want and backs it in the consumer's foreign group for the upstream. The upstream carries a manifest naming it `core-layers4-up`, and the spec links it into the world install for the run, so the import resolves to the upstream's directory and its published system.

The spec runs three legs over the same consumer, re-syncing between them:

1. Standalone (canonical config, no upstream). The sync warns `ATM-W-MISSING-CONTAINER-ROOT` once, with the text "no container root (container-type) is defined in globalCss". The compile request carries neither `upstreamContainerRoot` nor `upstreamSystems`, the sheet has no foreign group, the container probe stays at its 50px base and the foreign probe takes the body ink.
2. Layers (`layers: [up]`). The sync is silent. The request carries `upstreamContainerRoot: true` and `upstreamSystems: ["core-layers4-up"]`. The sheet states `@layer core-layers4-up, core-layers4;`, the upstream root rides the upstream block, and the consumer's foreign group `/* foreign core-layers4-up */` prints `.core-layers4-up__c_\#15803d`. The html element is an `inline-size` container, the probe paints 60px, and the foreign probe paints the literal green.
3. Extends (`extends: [up]`, the control). The same verdicts as layers, so the layer changes nothing the extends bucket does not already do.

The published entry is asserted too. The consumer's own published `baseSystem` carries no foreign group, while the served sheet keeps it. That publish-time strip is what keeps a foreign rule from reaching a downstream compose.

Observables found, with evidence:

- Container root verdict. The sync entry reads the root verdict across extends and layers together. The container-root scan detects a `:root`, `html` or `body` block declaring a container property in the published global text. The native request puts the key on the request. Assembly hands it to the check. The container-root check warns only when `@container` atoms exist, no upstream roots the page, and the local `globalCss` is non-empty. The code and text come from the diagnostics tables.
- Qualifiers. The sync entry builds `upstreamSystems` from extends then layers, self excluded. The native request serializes it. Assembly (`qualifiers_for`) makes the list own-first and deduped; it orders the groups but no longer decides what is emitted. The grouped utilities writer (`write_utilities_grouped`) writes one `/* foreign <q> */` group per system the foreign atoms name, composed systems first in qualifier order. The utilities layer printer prints the utilities layer when it has an own rule or a foreign group. The first-seen plan rule (`first_seen`) gives a declaration whose backing names no system no plan.
- What makes a want external. Import provenance: a tag whose import ends at a package that published a system is external whatever its name, and backs under that package's systems the consumer composes (provenance tracking, the package-system step reads the package's published system). The probe was first a same-file `Probe` that turned `color` into `data-probe-color`; since `edae6aa85` a same-file component's consumed prop is its own, so that probe minted no want and the layers leg failed on `public-release` too. The real consumer describes the same mechanism in the lib UI config, for `layers: [iconsBaseSystem]`.
- Foreign stripping. The stream printer (`stripForeignSections`) drops a foreign section from an entry. The publish step (`toPublishedEntry`) applies that to the own entry before it publishes, and this case asserts that leg. The upstream-block printer (`printUpstreamBlock`) applies it to upstream blocks at merge time. A real upstream never reaches that merge strip, because the publish strip has already removed every foreign group, so this case does not exercise it.
