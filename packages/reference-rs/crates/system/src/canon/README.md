# Canon: The Compiler Dictionary

The `canon` module provides the authoritative set of elements, style properties, aliases, and conditions recognized by the Reference UI styling engine. It acts as a static, allocation-free dictionary that compiler stages consult to validate syntax and normalize identifiers.

## Pass Integration and Rules

All compiler passes (`extract`, `resolve`, `stylesheet`, `runtime`) must import canonical lookups directly from `crate::canon`:
- **Extraction (`extract`)**: Inquires whether a JSX element is a Reference primitive, whether an attribute is a known style prop or alias, and whether an object key is a responsive condition.
- **Resolution (`resolve`)**: Normalizes dialect aliases to canonical properties and queries native shorthand longhand decompositions.
- **Stylesheet (`stylesheet`)**: Uses canonical declarations to determine utility class prefixes and generate kebab-case CSS properties.

Passes **must never copy or maintain their own lists** of tags, properties, or shorthands. All domain knowledge lives exclusively within the canon.

## Generated vs. Hand-Written Code

Files within this module (including `html.rs`, `css.rs`, `dialect.rs`, and `conditions.rs`) are strictly generated by `packages/reference-rs/canon/generate.ts`. Hand modifications to generated files will be overwritten. The module entrypoint (`mod.rs`) defines public lookup facades, and `tests.rs` asserts membership contracts and guards against hallucinated components.
